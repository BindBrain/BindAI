# Loops

Loop nodes allow a workflow to repeat part of its execution while a condition remains true.

Instead of duplicating workflow steps, a loop executes the same sequence multiple times, evaluating a predicate after each iteration.

Loops are useful for processing collections, polling external systems, batch operations, and other iterative workflows.

---

# What is a Loop?

A loop repeatedly executes a section of a workflow until its condition evaluates to **False**.

Conceptually:

```text
Loop

↓

Execute Body

↓

Evaluate Condition

↓

Repeat or Exit
```

Each iteration can read and update the workflow context.

---

# Why Use Loops?

Many automation scenarios require repeated execution.

Common examples include:

- processing a list of items
- polling an external API
- waiting for a background job
- validating data until complete
- paginating through results
- performing repeated calculations

Without loops, the same workflow steps would need to be duplicated.

---

# Loop Execution Flow

A loop creates a cycle in the workflow.

```text
Loop

↓

Body

↓

Condition

↙        ↘

Repeat    Exit
```

The workflow exits automatically once the condition becomes false.

---

# Creating a Loop

A loop node is added using the workflow builder.

```python
builder.loop(
    condition=lambda context: ...,
)
```

The loop condition receives the current execution context and returns a boolean.

---

# Loop Conditions

A condition determines whether another iteration should execute.

Example:

```python
lambda context: context.variables["counter"] < 5
```

As long as the expression evaluates to `True`, the workflow continues looping.

---

# Working with Variables

Loop conditions usually depend on workflow variables.

Example:

```text
counter = 0

↓

Loop

↓

counter = 1

↓

Loop

↓

counter = 2

↓

Loop

↓

counter = 3

↓

Exit
```

Variables are updated during each iteration.

---

# Example: Processing a Collection

A common pattern is iterating through a list.

```text
Initialize List

↓

Loop

↓

Process Current Item

↓

Next Item

↓

Repeat
```

The workflow exits once every item has been processed.

---

# Example: Polling an External Service

Loops are also useful for polling asynchronous operations.

```text
Check Status

↓

Completed?

↓

No

↓

Wait

↓

Repeat
```

When the service reports completion, execution continues to the next workflow step.

---

# Example: Batch Processing

A loop can process records one batch at a time.

```text
Load Batch

↓

Process Batch

↓

More Records?

↓

Yes

↓

Repeat
```

This approach scales better than processing everything in a single step.

---

# Loops vs Retry

Although they appear similar, loops and retry policies solve different problems.

| Loop | Retry |
| ---- | ----- |
| Repeats business logic | Repeats failed operations |
| Controlled by workflow variables | Triggered by execution failures |
| Part of workflow design | Part of reliability strategy |
| May execute indefinitely | Usually limited by retry policy |

Use retries for temporary failures.

Use loops when repeated execution is intentional.

---

# Nested Loops

Workflows may contain multiple loops.

```text
Outer Loop

↓

Inner Loop

↓

Continue
```

Nested loops are supported, but excessive nesting can reduce readability.

Whenever possible, keep workflows simple.

---

# Exiting a Loop

Every loop should eventually terminate.

```text
Condition

↓

False

↓

Continue Workflow
```

A terminating condition is essential for predictable execution.

---

# Avoiding Infinite Loops

The loop body should modify the state used by the condition.

Example:

```text
counter += 1

↓

Evaluate Condition

↓

Eventually False
```

If the controlling variables never change, the workflow may never finish.

---

# Shared Workflow Context

Every iteration uses the same execution context.

```text
Iteration 1

↓

Workflow Context

↓

Iteration 2

↓

Workflow Context

↓

Iteration 3
```

Variables accumulate across iterations unless explicitly reset.

This makes it easy to build incremental workflows.

---

# Combining Loops with Other Nodes

Loops work naturally with other workflow components.

For example:

```text
Loop

↓

Agent

↓

Condition

↓

Tool

↓

Repeat
```

Each iteration can execute agents, tools, conditions, or other workflow nodes.

---

# Common Use Cases

Loop nodes are commonly used for:

- iterating through collections
- batch processing
- pagination
- polling external services
- repeated validation
- waiting for approvals
- incremental synchronization
- scheduled checks

---

# Best Practices

- Always define a clear exit condition.
- Update the variables used by the loop condition.
- Keep loop bodies focused on a single responsibility.
- Avoid deeply nested loops when possible.
- Use retries instead of loops for transient failures.
- Monitor long-running loops in production workflows.

---

# Summary

Loop nodes allow BindAI workflows to repeat execution while a condition remains true.

By combining loop conditions with shared workflow variables, you can build clean, reusable, and maintainable workflows for iterative business processes without duplicating workflow logic.
