# Workflow Nodes

Workflow nodes are the fundamental building blocks of every BindAI workflow.

Each node performs a single task before passing execution to the next node.

By combining different node types, workflows can model everything from simple AI conversations to complex business automation.

---

# What is a Node?

A node represents one execution step.

Conceptually:

```text
Input

↓

Node

↓

Output
```

Every workflow is built by connecting multiple nodes together.

---

# Workflow Graph

Nodes form a directed execution graph.

```text
Start

↓

Agent

↓

Condition

↓

Tool

↓

End
```

Execution moves between nodes according to the workflow definition.

---

# Node Lifecycle

Although node types differ, every node follows the same lifecycle.

```text
Receive Context

↓

Execute

↓

Update Context

↓

Select Next Node
```

Each node receives the current workflow context, performs its work, updates the context if necessary, and transfers execution.

---

# Built-in Node Types

BindAI includes several built-in workflow nodes.

| Node | Purpose |
|------|---------|
| Start | Entry point of the workflow |
| End | Completes workflow execution |
| Agent | Executes an AI agent |
| Tool | Executes a registered tool |
| Condition | Branches execution |
| Loop | Repeats execution |
| Parallel | Starts multiple branches |
| Join | Synchronizes parallel branches |
| Human Task | Waits for manual approval |

Additional node types can be introduced in future releases.

---

# Start Node

Every workflow begins with a Start node.

```text
Start

↓

Next Node
```

The Start node initializes the workflow and creates the execution context.

There is exactly one Start node in every workflow.

---

# End Node

The End node finishes execution.

```text
Previous Node

↓

End
```

Once execution reaches the End node, the workflow completes and returns its result.

---

# Agent Node

Agent nodes execute BindAI agents.

```text
Workflow

↓

Agent

↓

Agent Result
```

The agent may:

- read workflow variables
- use tools
- retrieve knowledge
- access memory
- write results back into the workflow context

---

# Tool Node

Tool nodes execute Python tools directly.

```text
Workflow

↓

Tool

↓

Output
```

Unlike Agent nodes, Tool nodes execute deterministic application logic without involving a language model.

Typical use cases include:

- database queries
- API calls
- calculations
- file operations

---

# Condition Node

Condition nodes create branching logic.

```text
Condition

↙       ↘

True     False
```

Only one outgoing branch continues execution.

Conditions are commonly used for:

- approvals
- validations
- business rules
- workflow routing

---

# Loop Node

Loop nodes repeat execution until a condition is satisfied.

```text
Loop

↓

Body

↓

Condition

↓

Repeat or Exit
```

Typical scenarios include:

- processing collections
- retry logic
- polling external systems
- iterative workflows

---

# Parallel Node

Parallel nodes begin multiple branches simultaneously.

```text
Parallel

↙     ↓     ↘

A     B     C
```

Each branch executes independently.

Parallel execution can significantly reduce workflow execution time.

---

# Join Node

Join nodes synchronize multiple branches.

```text
Branch A

↓

Join

↑

Branch B
```

Execution continues only after all required branches have completed.

---

# Human Task Node

Human Task nodes pause execution until manual input is received.

```text
Workflow

↓

Human Task

↓

Waiting

↓

Resume
```

Typical uses include:

- approvals
- reviews
- compliance checks
- manual verification

---

# Context Sharing

Every node operates on the shared workflow context.

```text
Node A

↓

Workflow Context

↓

Node B
```

The context allows information to flow naturally through the workflow.

---

# Variables Between Nodes

Nodes communicate through workflow variables.

Example:

```text
Agent

↓

customer_name

↓

Condition

↓

Email Tool
```

A node can:

- read existing variables
- create new variables
- update existing values

---

# Custom Nodes

Developers can create custom workflow nodes.

A simplified implementation might look like this.

```python
class MyNode(WorkflowNode):
    async def execute(self, context): ...
```

Custom nodes integrate with the execution engine just like built-in nodes.

---

# Node Connections

Each node determines where execution continues.

```text
Node

↓

Next Node

↓

Next Node
```

Some node types have:

- one outgoing connection
- multiple outgoing branches
- dynamic routing based on runtime conditions

---

# Node Independence

Nodes should remain independent whenever possible.

A well-designed node should:

- perform one task
- read required context
- update context
- transfer execution

Small, focused nodes are easier to test, reuse, and maintain.

---

# Error Handling

If a node fails, workflow behavior depends on its configuration.

Possible strategies include:

- stop execution
- retry the node
- execute a fallback branch
- continue with default values

These strategies can be configured without changing node implementations.

---

# Best Practices

- Give every node one clear responsibility.
- Keep nodes small and reusable.
- Pass information through workflow variables.
- Separate orchestration from business logic.
- Prefer composing many simple nodes over a few complex ones.
- Use descriptive node names for easier debugging.
- Use Agent nodes for reasoning and Tool nodes for deterministic work.

---

# Summary

Workflow nodes are the execution units of BindAI workflows.

Each node performs one well-defined task while sharing information through the workflow context. By combining different node types, developers can build modular, reliable, and maintainable AI workflows that scale from simple automations to complex enterprise systems.
