# Workflow Builder

The **Workflow Builder** is the primary way to create workflows in BindAI.

Instead of manually constructing workflow graphs and managing node relationships, the builder provides a fluent API that lets you define workflows step by step.

It automatically manages node registration, connections, and validation before the workflow is executed.

---

# Why Use the Workflow Builder?

Workflows are directed graphs composed of connected nodes.

As workflows become more complex, manually managing those connections becomes difficult.

The builder simplifies this by allowing you to focus on workflow logic instead of graph implementation.

Benefits include:

- readable workflow definitions
- automatic node connections
- validation before execution
- easier maintenance
- reusable workflow patterns

---

# Builder Lifecycle

Every workflow follows the same construction process.

```text
Create Builder

↓

Add Nodes

↓

Connect Nodes

↓

Validate

↓

Build Workflow
```

Once built, the workflow becomes immutable and ready for execution.

---

# Creating a Builder

Create a new workflow builder.

```python
from bindai_workflow import WorkflowBuilder

builder = WorkflowBuilder(
    name="Customer Support",
)
```

At this stage, the workflow exists only in memory.

---

# Defining the Start Node

Every workflow begins with a start node.

```python
builder.start_node()
```

The start node represents the entry point for workflow execution.

A workflow can only have one start node.

---

# Adding Nodes

Nodes are added one after another.

```python
builder.start_node()

builder.agent(
    support_agent,
)

builder.end_node()
```

For sequential workflows, each node is automatically connected to the previous one.

---

# Fluent Builder Pattern

The builder supports fluent chaining.

```python
workflow = (
    WorkflowBuilder(
        name="Example",
    )
    .start_node()
    .agent(agent)
    .end_node()
    .build()
)
```

This style is concise and works well for smaller workflows.

---

# Building the Workflow

When construction is complete, build the workflow.

```python
workflow = builder.build()
```

During this step, BindAI validates the graph before returning the finished workflow.

---

# Validation

The builder automatically validates the workflow structure.

Common validation checks include:

- exactly one start node
- reachable nodes
- valid node connections
- duplicate node identifiers
- missing end nodes
- invalid graph structure

Validation helps catch problems before runtime.

---

# Registering Agents

When an agent node is added, the builder registers the agent automatically.

```text
Agent

↓

Workflow Builder

↓

Workflow Registry
```

During execution, agent nodes reference the registered agent instead of storing their own copies.

---

# Sequential Workflows

The simplest workflow executes one node after another.

```text
Start

↓

Agent

↓

Tool

↓

End
```

Each node begins only after the previous node completes.

---

# Conditional Branches

Builders can create conditional execution paths.

```text
Agent

↓

Condition

↙        ↘

True     False
```

Only one branch continues based on the evaluated condition.

---

# Loops

Loops allow portions of a workflow to repeat.

```text
Node

↓

Condition

↓

Repeat

↓

Continue
```

Execution continues until the loop condition is no longer satisfied.

---

# Parallel Execution

Builders can also execute branches simultaneously.

```text
Parallel

↙      ↓      ↘

A      B      C

↓

Join
```

Each branch executes independently before synchronization.

Parallel execution is useful for independent tasks such as:

- multiple API calls
- document processing
- parallel agents
- concurrent analysis

---

# Human Tasks

Human approval can be inserted anywhere in a workflow.

```text
Agent

↓

Human Task

↓

Resume

↓

Continue
```

The workflow pauses until the required user action is completed.

---

# Workflow Variables

Nodes communicate through workflow variables rather than direct references.

```text
Node A

↓

Workflow Variables

↓

Node B
```

This keeps nodes loosely coupled and easier to reuse.

---

# Organizing Large Workflows

Large workflows are easier to understand when organized into logical stages.

Example:

```text
Start

↓

Preparation

↓

Processing

↓

Validation

↓

Completion
```

Grouping related responsibilities improves readability and maintenance.

---

# Nested Workflows

Complex systems can often be divided into smaller workflows.

Instead of creating one extremely large workflow, consider composing multiple focused workflows that each solve a single problem.

This makes testing and debugging significantly easier.

---

# Builder Benefits

Using the Workflow Builder provides several advantages:

- automatic graph construction
- fluent syntax
- built-in validation
- readable workflow definitions
- easier maintenance
- reusable workflow components

---

# Best Practices

- Begin with a clear workflow objective.
- Keep each node focused on one responsibility.
- Use fluent chaining for simple workflows.
- Split large workflows into logical stages.
- Use workflow variables to exchange data.
- Validate workflows before deployment.
- Prefer several small workflows over one very large workflow.
- Keep orchestration separate from business logic.

---

# Summary

The Workflow Builder provides a fluent, structured way to create workflow graphs in BindAI.

By handling node registration, graph construction, and validation automatically, it allows developers to focus on workflow behavior instead of implementation details.
