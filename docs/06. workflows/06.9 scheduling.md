# Scheduling

Scheduling allows workflows to execute automatically at specific times or recurring intervals.

Instead of manually triggering a workflow, BindAI can run it whenever its configured schedule becomes due.

Scheduling is useful for automation, monitoring, reporting, maintenance, and recurring AI tasks.

---

# What is Workflow Scheduling?

A schedule defines **when** a workflow should run.

Conceptually:

```text
Schedule

↓

Time Reached

↓

Execute Workflow
```

The scheduler continuously checks registered schedules and starts workflows when they become due.

---

# Why Schedule Workflows?

Many AI and business processes are repetitive.

Common examples include:

- daily reports
- hourly monitoring
- nightly backups
- document processing
- recurring summarization
- knowledge synchronization
- notification delivery
- scheduled maintenance

Scheduling automates these tasks without user intervention.

---

# Scheduler Architecture

BindAI separates scheduling from workflow execution.

```text
Workflow Schedule

↓

Scheduler

↓

Workflow Executor

↓

Workflow Result
```

The scheduler determines **when** a workflow should run.

The executor determines **how** it runs.

---

# Workflow Schedule

A workflow schedule stores information about when a workflow should execute.

Typical properties include:

- workflow identifier
- next execution time
- execution interval
- enabled state
- metadata

Conceptually:

```python
WorkflowSchedule(
    workflow_id="daily-report",
    next_run=...,
    interval_seconds=3600,
)
```

---

# Scheduler

The scheduler manages all registered workflow schedules.

```text
Schedule A

Schedule B

Schedule C

↓

Scheduler

↓

Due Workflows
```

Only workflows whose scheduled execution time has arrived are started.

---

# Detecting Due Workflows

During each scheduler cycle:

```text
Current Time

↓

Compare With Schedule

↓

Due?

↓

Execute
```

Schedules whose execution time is still in the future remain idle.

---

# Recurring Workflows

Recurring schedules automatically calculate their next execution time.

```text
Run

↓

Calculate Next Run

↓

Run Again

↓

Calculate Next Run
```

This allows workflows to execute indefinitely on a defined interval.

---

# One-Time Execution

Schedules may also execute only once.

```text
Scheduled Time

↓

Execute Workflow

↓

Completed
```

After completion, no further executions occur unless another schedule is created.

---

# Rescheduling

After a recurring workflow completes successfully, the scheduler computes its next execution time.

```text
Workflow Finished

↓

Add Interval

↓

Store Next Run
```

This process is handled automatically.

# Background Automation

Scheduling enables fully automated systems.

Examples include:

- checking system health
- generating summaries
- refreshing embeddings
- synchronizing external systems
- sending reminder emails
- processing queued documents
- cleaning temporary files

These workflows execute without manual interaction.

---

# Scheduling vs Loops

Although both involve repeated execution, they solve different problems.

| Scheduling | Loops |
| ---------- | ----- |
| Executes over time | Executes immediately |
| Time-based | Logic-based |
| Persistent | Single workflow execution |
| Background automation | Runtime iteration |

Loops repeat during one execution.

Schedules create entirely new executions in the future.

---

# Time Zones

Production scheduling should always use timezone-aware timestamps.

This helps avoid issues caused by:

- daylight saving time
- server location differences
- UTC vs local time
- regional deployments

Consistent timezone handling improves reliability.

---

# Enabling and Disabling

Schedules can be enabled or disabled without being deleted.

```text
Enabled

↓

Execute

Disabled

↓

Ignored
```

Disabled schedules remain registered but will not trigger workflow execution.

---

# Preventing Overlapping Runs

Long-running workflows may overlap with future scheduled executions.

Applications commonly choose one of the following strategies:

- allow concurrent executions
- skip overlapping runs
- queue pending executions
- delay the next execution until completion

The appropriate behavior depends on your workload.

---

# Monitoring Scheduled Workflows

Production systems should monitor scheduled executions.

Useful metrics include:

- execution frequency
- execution duration
- success rate
- failures
- missed schedules
- retry attempts

Monitoring helps identify scheduling problems before they impact users.

---

# Best Practices

- Use timezone-aware datetime values.
- Keep scheduled workflows idempotent whenever possible.
- Monitor recurring executions.
- Choose reasonable execution intervals.
- Avoid unnecessary overlapping executions.
- Log execution history.
- Handle failures and retries appropriately.

---

# Summary

Workflow scheduling allows BindAI to execute workflows automatically according to predefined schedules.

By separating scheduling from execution, BindAI provides a flexible foundation for recurring automation while keeping workflow logic independent from timing concerns.
