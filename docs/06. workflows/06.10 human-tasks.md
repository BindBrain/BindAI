# Human Tasks

Human Tasks allow a workflow to pause execution and wait for a person to review, approve, reject, or provide additional information before continuing.

This enables **human-in-the-loop** workflows, where AI automation and human decision-making work together.

Human Tasks are essential for business processes that require oversight, compliance, or manual approval.

---

# What is a Human Task?

A Human Task temporarily suspends workflow execution until someone completes the required action.

```text
Workflow

↓

Human Task

↓

Waiting

↓

User Decision

↓

Resume Workflow
```

During the waiting period, the workflow remains paused.

---

# Why Use Human Tasks?

Not every decision should be automated.

Human Tasks are commonly used for:

- approving payments
- reviewing contracts
- validating AI-generated content
- approving refunds
- security reviews
- compliance verification
- publishing content
- customer service escalation

These tasks ensure that critical decisions remain under human control.

---

# Workflow Lifecycle

When a Human Task is reached, the execution lifecycle changes.

```text
Workflow Running

↓

Create Human Task

↓

Pause Workflow

↓

Wait for Completion

↓

Resume Workflow

↓

Continue Execution
```

Execution resumes from exactly where it stopped.

---

# Creating a Human Task

A Human Task node creates a task record that can be completed later.

Typical information includes:

- task identifier
- workflow instance identifier
- node identifier
- assigned user or role
- creation timestamp
- completion status
- task result

Applications can expose this information through dashboards or approval interfaces.

---

# Waiting State

After creating the task, the workflow enters a waiting state.

```text
Running

↓

Waiting

↓

Completed

↓

Running
```

While waiting:

- no additional nodes execute
- workflow state is preserved
- variables remain available
- execution can resume later

---

# Completing a Task

A person or external application completes the task.

```text
Open Task

↓

Review

↓

Approve or Reject

↓

Resume Workflow
```

Once completed, the workflow automatically continues.

---

# Approval Example

A document approval workflow might look like this.

```text
Generate Contract

↓

Human Approval

↓

Approved?

↓

Continue
```

The workflow does not proceed until a reviewer submits a decision.

# AI + Human Collaboration

Human Tasks integrate naturally with AI agents.

```text
AI Agent

↓

Draft Proposal

↓

Human Review

↓

Publish
```

The AI performs repetitive work while humans remain responsible for important decisions.

---

# Workflow Context

Human Tasks typically store their result inside the workflow context.

Example:

```text
approved = true

comments = "Looks good."
```

Subsequent workflow nodes can use these values when making decisions.

---

# Using Task Results

A later condition may evaluate the approval result.

```text
Human Task

↓

approved?

├── Yes → Continue

└── No → Revise
```

This allows workflows to branch based on human decisions.

---

# Forms and User Interfaces

Human Tasks are independent of the user interface.

A typical flow looks like this.

```text
Workflow

↓

Human Task

↓

Approval Form

↓

Submit

↓

Workflow Resumes
```

BindAI manages the workflow state, while your application provides the interface for reviewers.

# Assignment

Tasks can be assigned to:

- individual users
- teams
- departments
- roles
- external systems

Assignment logic is handled by the surrounding application rather than the workflow engine itself.

---

# Long-Running Workflows

Human Tasks allow workflows to remain paused for extended periods.

```text
Day 1

↓

Waiting

↓

Day 4

↓

Approved

↓

Resume Workflow
```

Workflows may remain suspended for minutes, hours, days, or even weeks.

---

# Human Tasks vs Conditions

Although they are often used together, they solve different problems.

| Human Task | Condition |
| ----------- | --------- |
| Waits for a person | Evaluates logic automatically |
| Requires manual input | Uses workflow variables |
| May pause for days | Executes immediately |
| Human decision | Programmatic decision |

Conditions automate decisions.

Human Tasks defer decisions to people.

---

# Human Tasks vs AI Agents

Agents generate content or make recommendations.

Human Tasks collect final decisions.

```text
AI Agent

↓

Recommendation

↓

Human Task

↓

Final Decision
```

This pattern is common in enterprise automation.

---

# Best Practices

- Use Human Tasks only where human judgment is required.
- Keep task descriptions clear and concise.
- Store important decisions as workflow variables.
- Separate workflow logic from user interface implementation.
- Assign meaningful task identifiers.
- Monitor pending tasks to prevent workflows from remaining paused indefinitely.
- Record reviewer comments when appropriate.

---

# Summary

Human Tasks allow BindAI workflows to pause safely while waiting for manual input.

They provide the foundation for human-in-the-loop automation by combining AI efficiency with human judgment, accountability, and oversight.
