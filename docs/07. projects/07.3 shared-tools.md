# Shared Tools

Shared Tools allow multiple agents, workflows, and applications within a BindAI project to reuse the same functionality.

Instead of implementing the same tool repeatedly, you can register it once at the project level and make it available everywhere it is needed.

This improves consistency, maintainability, and code reuse.

---

# What are Shared Tools?

A shared tool is a reusable tool that belongs to the project rather than an individual agent.

Conceptually:

```text
Project

↓

Tool Registry

↓

Applications

↓

Agents
```

Any registered tool can be used by multiple agents throughout the project.

---

# Why Use Shared Tools?

Without shared tools, projects often duplicate functionality.

For example:

```text
Support Agent

↓

Database Lookup

Sales Agent

↓

Database Lookup

HR Agent

↓

Database Lookup
```

Instead of maintaining three identical implementations, BindAI encourages one shared tool.

Benefits include:

- reduced code duplication
- centralized maintenance
- consistent behavior
- easier testing
- simpler upgrades

---

# Project Tool Registry

Projects maintain a centralized registry of reusable tools.

```text
Project

↓

Shared Tool Registry

├── Search
├── Database
├── Email
├── Calendar
├── Weather
└── CRM
```

Agents access tools from this registry instead of defining their own copies.

---

# Registering Shared Tools

Register a tool once at the project level.

```python
project.add_tool(
    search_tool,
)
```

After registration, every application inside the project can access it.

---

# Using Shared Tools

Agents automatically use shared tools during execution.

```text
Agent

↓

Shared Tool

↓

Tool Result

↓

Final Response
```

The agent does not need to know where the tool was originally implemented.

---

# Reusing Tools

One tool implementation can support many agents.

```text
Shared Search Tool

↙      ↓      ↘

Support

Sales

Research
```

Updates to the tool automatically benefit every consumer.

---

# Typical Shared Tools

Frequently shared tools include:

- database queries
- web search
- email delivery
- calendar integration
- document retrieval
- file storage
- CRM integration
- payment services
- weather lookup
- internal APIs

These services are commonly needed by many agents.

---

# Shared Tools vs Local Tools

Not every tool should be shared.

| Shared Tool | Local Tool |
| ------------ | ---------- |
| Used by many agents | Used by one agent |
| Registered at project level | Registered directly on the agent |
| Highly reusable | Task-specific |
| Centrally maintained | Independently maintained |

If only one agent uses a tool, keeping it local may be simpler.

---

# Organizing Shared Tools

As projects grow, organize tools into logical modules.

```text
tools/

├── communication/
├── database/
├── retrieval/
├── integrations/
├── utilities/
└── analytics/
```

A clear structure makes tools easier to discover and maintain.

---

# Versioning

Many agents may depend on the same tool.

When updating shared tools:

- preserve backward compatibility whenever possible
- test changes before deployment
- document interface changes
- avoid unnecessary breaking changes

Stable interfaces reduce maintenance across the project.

---

# Security

Shared tools often access sensitive systems.

Examples include:

- databases
- cloud storage
- payment systems
- internal APIs
- customer information

Protect these tools by:

- validating inputs
- limiting permissions
- handling errors safely
- avoiding secret exposure
- auditing important operations

---

# Performance

Frequently used shared tools should be optimized.

Consider:

- caching results
- connection pooling
- batching requests
- asynchronous execution
- minimizing network calls

Performance improvements benefit every application using the tool.

---

# Testing

Because shared tools are reused throughout a project, they should be thoroughly tested.

Recommended tests include:

- valid inputs
- invalid inputs
- failure scenarios
- external service outages
- performance under load

Reliable shared tools improve the stability of every agent.

---

# Best Practices

- Share only tools that are genuinely reusable.
- Keep each tool focused on one responsibility.
- Use descriptive names and docstrings.
- Maintain stable interfaces.
- Validate inputs before execution.
- Handle failures gracefully.
- Organize tools into logical modules.
- Test shared tools thoroughly before updating them.

---

# Summary

Shared Tools provide a centralized way to reuse functionality across BindAI projects.

By registering tools once and making them available to multiple agents and workflows, projects become easier to maintain, more consistent, and significantly less repetitive.
