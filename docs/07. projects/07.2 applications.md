# Applications

An **Application** is a self-contained AI service within a BindAI project.

Applications group together agents, workflows, prompts, configuration, and runtime behavior for a specific business domain.

A single project can contain multiple applications that share common infrastructure while remaining logically independent.

---

# What is an Application?

An application is the primary runtime unit of a BindAI project.

Conceptually:

```text
Project

↓

Application

↓

Agents / Workflows

↓

Responses
```

Users interact with applications, not directly with individual agents.

---

# Why Use Applications?

As AI systems grow, different business problems usually require different behavior.

For example:

- Customer Support
- Internal Knowledge Assistant
- HR Assistant
- Sales Automation
- Document Analysis
- Code Review

Instead of placing everything into one large system, each domain can become its own application.

---

# Application Architecture

A typical application contains:

```text
Application

├── Agents

├── Workflows

├── Prompts

├── Configuration

└── Runtime
```

Applications can also access project-level resources such as shared tools, memory providers, and knowledge sources.

---

# Multiple Applications

A single project may host several independent applications.

```text
Project

├── Customer Support

├── HR Assistant

├── Finance Assistant

├── Analytics

└── Engineering Assistant
```

Each application focuses on one business area while sharing common infrastructure.

---

# Agents Inside Applications

Applications usually contain one or more agents.

```text
Application

↓

Support Agent

↓

Language Model
```

Each agent performs a specialized task within the application's domain.

For example, a support application might include:

- FAQ agent
- escalation agent
- billing agent

---

# Workflows Inside Applications

Applications frequently execute workflows rather than individual agents.

```text
User Request

↓

Application

↓

Workflow

↓

Multiple Agents

↓

Final Result
```

Workflows coordinate complex business processes while the application provides a simple entry point.

---

# Shared Project Resources

Applications can reuse project-wide resources.

Examples include:

- shared tools
- shared workflows
- shared prompts
- shared knowledge bases
- shared memory providers
- shared middleware

This reduces duplication and keeps behavior consistent across applications.

---

# Running an Application

Applications expose a simple execution interface.

Conceptually:

```python
result = project.run(
    application="support",
    message="How do I reset my password?",
)
```

The application determines which workflow or agent should process the request.

---

# Streaming Responses

Applications support streaming output.

```text
User

↓

Application

↓

Agent

↓

Streaming Response
```

Streaming is especially useful for chat interfaces and long responses.

---

# Application Configuration

Each application maintains its own configuration.

Typical configuration includes:

- default language model
- available agents
- enabled workflows
- provider settings
- prompts
- metadata

Configuration remains isolated from other applications inside the same project.

---

# Application Lifecycle

A typical request follows this flow.

```text
Request

↓

Application

↓

Agent or Workflow

↓

Language Model

↓

Response

↓

Return Result
```

The application manages orchestration while agents perform reasoning.

---

# Separation of Responsibilities

Each application should focus on a single business domain.

Good examples:

```text
Customer Support

Human Resources

Finance

Engineering

Sales
```

Avoid creating one application responsible for unrelated tasks.

---

# Applications vs Projects

Projects and applications serve different purposes.

| Project | Application |
| -------- | ----------- |
| Top-level container | Individual AI service |
| Contains multiple applications | Contains agents and workflows |
| Owns shared infrastructure | Owns business logic |
| Manages resources | Handles user requests |

Projects organize.

Applications execute.

---

# Typical Directory Structure

An application might look like this:

```text
support/

├── agents/

├── workflows/

├── prompts/

├── configuration/

├── tools/

└── resources/
```

The exact structure depends on your project's requirements.

---

# Scaling Applications

As an application grows, you can add:

- more agents
- additional workflows
- specialized prompts
- new tools
- dedicated knowledge sources
- application-specific middleware

Because applications remain isolated, expanding one application does not affect the others.

---

# Best Practices

- Create one application per business domain.
- Keep application responsibilities focused.
- Reuse shared project resources whenever possible.
- Register only the agents required by that application.
- Keep configuration local to the application.
- Prefer multiple focused applications over one monolithic application.
- Design applications with clear entry points.

---

# Summary

Applications are the runtime services inside a BindAI project.

They organize agents, workflows, prompts, and configuration into focused AI solutions while sharing common project infrastructure such as tools, knowledge, memory, and middleware.
