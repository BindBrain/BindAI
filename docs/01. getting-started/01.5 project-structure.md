# Project Structure

BindAI projects provide a consistent structure for organizing agents, tools, workflows, knowledge, memory, templates, and tests.

You can use BindAI components without creating a project, but a project provides a convenient way to keep application configuration and components organized.

---

# Creating a Project

Create a new project with the BindAI CLI:

```bash
bindai new my-ai-app
```

Move into the project:

```bash
cd my-ai-app
```

The generated project provides a starting point for building an AI application.

---

# Default Project Layout

A generated project can contain a structure similar to:

```text
my-ai-app/

├── agents/
│   └── assistant.py
│
├── tools/
│   └── echo.py
│
├── workflows/
│
├── knowledge/
│
├── memory/
│
├── templates/
│
├── tests/
│
├── .env.example
├── .gitignore
├── bindai.toml
├── LICENSE
├── README.md
├── requirements.txt
└── main.py
```

The exact generated files may change as the project templates evolve.

Each directory has a specific responsibility.

---

# Project Files

## `main.py`

The application's entry point.

A project can use `main.py` to create or load an agent and start application execution.

For example:

```python
from agents.assistant import agent

result = agent.run("Hello!")

print(result.output)
```

The exact application entry point depends on how the project is configured.

---

## `bindai.toml`

`bindai.toml` contains project-level BindAI configuration.

For example:

```toml
provider = "openai"
model = "gpt-4.1-mini"
temperature = 0.7
```

Project configuration can be used to keep model and application settings outside the Python source code.

Agents can load project configuration through `AgentBuilder`:

```python
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .from_project()
    .build()
)
```

The configuration available to the agent depends on the project's configuration and registered components.

---

## `.env.example`

`.env.example` provides a template for environment variables used by the application.

For example:

```text
OPENAI_API_KEY=
OPENAI_ORGANIZATION=
OPENAI_BASE_URL=
```

Create a local `.env` file from the example when required:

### macOS / Linux

```bash
cp .env.example .env
```

### Windows PowerShell

```powershell
Copy-Item .env.example .env
```

Keep API keys and other secrets out of source control.

---

## `requirements.txt`

`requirements.txt` can contain Python dependencies required by the generated project.

For example:

```text
bindai
python-dotenv
```

Install the dependencies with:

```bash
pip install -r requirements.txt
```

For projects using a different dependency-management workflow, follow that project's configuration instead.

---

# Agents

The `agents/` directory contains application-specific agents.

A simple project might contain:

```text
agents/

└── assistant.py
```

An agent can be configured with `AgentBuilder`:

```python
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .instructions("You are a helpful assistant.")
    .build()
)
```

Larger applications can organize multiple specialized agents:

```text
agents/

├── assistant.py
├── researcher.py
├── planner.py
└── reviewer.py
```

Each agent can be configured independently while sharing the same project structure.

---

# Tools

The `tools/` directory contains reusable tools that can be attached to agents.

For example:

```text
tools/

├── weather.py
├── search.py
├── calculator.py
└── database.py
```

A simple tool can be defined using the BindAI `tool` decorator:

```python
from bindai import tool


@tool
def echo(text: str):
    return text
```

Tools can then be configured on an agent:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .tools(echo)
    .build()
)
```

Project-based tool loading depends on the project configuration and loader implementation.

---

# Workflows

The `workflows/` directory contains workflow-related application code.

For example:

```text
workflows/

├── approval.py
├── onboarding.py
└── report_generation.py
```

Workflows can coordinate application logic such as:

* Multiple agents
* Conditional execution
* Loops
* Parallel execution
* Human tasks
* Retries
* Timeouts
* Scheduling

Keeping workflows separate from agents and tools makes larger applications easier to maintain.

---

# Knowledge

The `knowledge/` directory can contain application resources used by knowledge and retrieval systems.

For example:

```text
knowledge/

├── handbook.pdf
├── policies.md
├── faq.md
└── api_reference.pdf
```

Knowledge resources can be connected to agents through BindAI's knowledge APIs.

For example:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .knowledge(knowledge)
    .build()
)
```

The way documents are indexed and retrieved depends on the configured knowledge and retrieval components.

---

# Memory

The `memory/` directory can be used to organize project-specific memory resources or implementations.

Depending on the application, memory may use:

* Local storage
* Databases
* Vector storage
* External services
* Custom memory implementations

Memory can be configured through the agent builder:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .memory(memory)
    .build()
)
```

The actual storage mechanism depends on the selected memory implementation.

---

# Templates

The `templates/` directory can contain reusable prompt or application templates.

For example:

```text
templates/

├── email.md
├── summarize.md
└── review.md
```

Templates help keep repeated application instructions and prompt structures organized.

---

# Tests

Store project tests inside the `tests/` directory.

For example:

```text
tests/

├── test_agents.py
├── test_tools.py
└── test_workflows.py
```

Run the project's test suite with:

```bash
pytest
```

The exact test configuration depends on the project's Python environment and test setup.

---

# Loading Project Configuration

`AgentBuilder` provides `from_project()` for project-based agent configuration.

```python
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .from_project()
    .build()
)
```

This allows project configuration to be separated from application code.

Project-based configuration can include settings such as:

* Provider configuration
* Model configuration
* Agent instructions
* Tools
* Memory
* Knowledge
* Retrieval
* Middleware

The components loaded depend on the project's configuration.

# Organizing Larger Projects

As an application grows, organize components by responsibility.

For example:

```text
my-ai-app/

├── agents/
│   ├── assistant.py
│   ├── planner.py
│   └── researcher.py
│
├── tools/
│   ├── search.py
│   ├── weather.py
│   └── github.py
│
├── workflows/
│   ├── support.py
│   ├── onboarding.py
│   └── reports.py
│
├── knowledge/
│   ├── docs/
│   ├── manuals/
│   └── policies/
│
├── memory/
│
├── templates/
│
├── tests/
│
├── bindai.toml
├── main.py
└── .env
```

This separation makes it easier to locate components and extend the application without placing all of the logic in a single module.

---

# Recommended Development Workflow

A typical BindAI project workflow is:

1. Create a project with `bindai new`
2. Configure project settings
3. Configure environment variables
4. Build agents inside `agents/`
5. Add reusable tools inside `tools/`
6. Configure knowledge and retrieval when needed
7. Add memory when conversational state is required
8. Create workflows as application complexity grows
9. Add reusable templates
10. Write tests inside `tests/`

The project structure is intentionally modular so an application can grow from a simple assistant into a larger AI system without requiring all components to live in the same module.
