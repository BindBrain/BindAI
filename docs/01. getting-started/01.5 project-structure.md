# Project Structure

BindAI projects follow a simple, predictable structure that keeps agents, tools, workflows, and knowledge organized.

While you can use BindAI without a project, the recommended approach is to create one using the CLI.

---

# Creating a Project

Create a new project with the BindAI CLI.

```bash
bindai new my-ai-app
```

This generates a production-ready project structure.

---

# Default Project Layout

A newly created project looks like this.

```text
my-ai-app/

├── agents/
│   └── assistant.py
│
├── tools/
│   └── echo.py
│
├── workflows/
│
├── knowledge/
│
├── memory/
│
├── templates/
│
├── tests/
│
├── .env.example
├── .gitignore
├── bindai.toml
├── LICENSE
├── README.md
├── requirements.txt
└── main.py
```

Every directory has a specific responsibility.

---

# Project Files

## main.py

The application's entry point.

```python
from agents.assistant import agent

result = agent.run("Hello!")

print(result.output)
```

Most applications start here.

---

## bindai.toml

The project configuration file.

Example:

```toml
provider = "openai"
model = "gpt-4.1-mini"
temperature = 0.7
```

This file defines the default provider and model for the entire project.

Instead of configuring every agent manually, BindAI loads these defaults automatically through the project runtime.

---

## .env.example

Contains environment variables required by providers.

Example:

```text
OPENAI_API_KEY=
OPENAI_ORGANIZATION=
OPENAI_BASE_URL=
```

Create a `.env` file from this template before running your application.

---

## requirements.txt

Lists Python dependencies required by the project.

Example:

```text
bindai
python-dotenv
```

Install them using:

```bash
pip install -r requirements.txt
```

---

# Agents

The `agents/` directory contains reusable AI agents.

Example:

```text
agents/

└── assistant.py
```

```python
from bindai import Agent

agent = Agent(provider="openai", model="gpt-4.1-mini", instructions="You are a helpful assistant.")
```

Larger projects commonly include multiple agents.

Example:

```text
agents/

├── assistant.py
├── researcher.py
├── planner.py
└── reviewer.py
```

---

# Tools

The `tools/` directory stores reusable functions that agents can call.

Example:

```text
tools/

├── weather.py
├── search.py
├── calculator.py
└── database.py
```

Example tool:

```python
from bindai import tool


@tool
def echo(text: str):

    return text
```

BindAI automatically discovers tools when using `AgentBuilder().from_project()`.

---

# Workflows

The `workflows/` directory contains workflow definitions.

Example:

```text
workflows/

├── approval.py
├── onboarding.py
└── report_generation.py
```

Workflows orchestrate:

* Multiple agents
* Conditional logic
* Parallel execution
* Loops
* Human approval
* Scheduling

---

# Knowledge

The `knowledge/` directory stores documents used for Retrieval-Augmented Generation (RAG).

Example:

```text
knowledge/

├── handbook.pdf
├── policies.md
├── faq.md
└── api_reference.pdf
```

These files are indexed and retrieved during agent execution.

---

# Memory

The `memory/` directory stores local memory-related resources.

Depending on the configured provider, this may include:

* Vector databases
* SQLite files
* Local indexes

Many projects use external databases instead.

---

# Templates

The `templates/` directory contains reusable prompt templates.

Example:

```text
templates/

├── email.md
├── summarize.md
└── review.md
```

Templates help standardize prompts across multiple agents.

---

# Tests

Store project tests inside the `tests/` directory.

Example:

```text
tests/

├── test_agents.py
├── test_tools.py
└── test_workflows.py
```

Run all tests with:

```bash
pytest
```

---

# Loading the Project Automatically

The easiest way to build agents is from the project configuration.

```python
from bindai import AgentBuilder

agent = AgentBuilder().from_project().build()
```

This automatically loads:

* bindai.toml
* Environment variables
* Registered tools
* Default model
* Temperature

allowing agents to be configured with minimal code.

# Scaling Projects

As projects grow, organize them by feature.

Example:

```text
my-ai-app/

agents/
    assistant.py
    planner.py
    researcher.py

tools/
    search.py
    weather.py
    github.py

workflows/
    support.py
    onboarding.py
    reports.py

knowledge/
    docs/
    manuals/
    policies/

tests/
```

Keeping responsibilities separated makes applications easier to maintain and extend.

---

# Recommended Workflow

A typical BindAI development workflow is:

1. Create a project with `bindai new`
2. Configure the model in `bindai.toml`
3. Add API keys to `.env`
4. Build agents inside `agents/`
5. Add reusable tools to `tools/`
6. Store documents in `knowledge/`
7. Create workflows as the application grows
8. Write tests in `tests/`

Following this structure ensures your project remains organized as it scales from a simple assistant to a production-ready AI application.
