# Installation

This guide walks you through installing BindAI and preparing your development environment.

There are two main ways to use BindAI:

- Install the published packages from PyPI — recommended for application development.
- Clone the GitHub repository and use the `uv` workspace — recommended for contributors and framework development.

## Requirements

Before installing BindAI, make sure you have:

- Python **3.12 or newer**
- pip
- Git (recommended for source development)
- [uv](https://docs.astral.sh/uv/) for source development

Verify your Python version:

```bash
python --version
```

BindAI v0.1 requires Python 3.12 or newer.

## Install BindAI from PyPI

The easiest way to install BindAI is from PyPI:

```bash
python -m pip install bindai
```

You can also use:

```bash
pip install bindai
```

After installation, verify the BindAI CLI:

```bash
bindai version
```

The CLI version changes as BindAI is released. Do not rely on a hardcoded version number in your application or documentation.

## Verify the Python Package

Verify that the BindAI Python package is available:

```bash
python -c "import bindai; print('BindAI import OK')"
```

Expected output:

```text
BindAI import OK
```

## Install Optional BindAI Packages

BindAI is organized into multiple packages.

The main `bindai` package provides the core framework experience. Additional capabilities are available through separate packages.

### REST API

Install the BindAI REST API package:

```bash
python -m pip install bindai-api
```

This package provides HTTP endpoints for:

- Agent execution

- Workflow execution
- Project access
- Background automation runs
- Run status
- Health checks

### Connections

Install the BindAI Connections package:

```bash
python -m pip install bindai-connections
```

## Create Your First Project

Generate a new BindAI project:

```bash
bindai new my-agent
```

Move into the generated project:

```bash
cd my-agent
```

The generated project provides the structure needed to build a BindAI application.

## Configure Environment Variables

AI providers generally require credentials.

Configure the required credentials in your environment or project `.env` file.

For example:

```text
OPENAI_API_KEY=your_api_key_here
```

Depending on the provider you use, other environment variables may be required.

Common provider credentials include:

```text
OPENAI_API_KEY=your_api_key_here
ANTHROPIC_API_KEY=your_api_key_here
GEMINI_API_KEY=your_api_key_here
GROQ_API_KEY=your_api_key_here
OPENROUTER_API_KEY=your_api_key_here
```

Local providers such as Ollama may not require a hosted API key.

Keep API keys and other credentials out of source control.

## Verify Your Environment

Run the built-in diagnostics:

```bash
bindai doctor
```

The doctor command checks the BindAI environment and reports detected configuration or installation issues.

## Run Your Project

Start the generated application:

```bash
bindai run
```

If the required configuration is available, the generated project can start its BindAI application environment.

## Docker Deployment

BindAI v0.1 includes Docker support for running the BindAI API service.

From the BindAI repository root, build the Docker image:

```bash
docker build -t bindai-api .
```

Run the container on Windows PowerShell:

```powershell
docker run --rm -p 8000:8000 `
  -e BINDAI_API_KEY=your-secret-key `
  bindai-api
```

On macOS or Linux:

```bash
docker run --rm -p 8000:8000 \
  -e BINDAI_API_KEY=your-secret-key \
  bindai-api
```

The API will be available at:

```text
http://localhost:8000
```

Verify the service with the health endpoint:

```text
http://localhost:8000/health
```

The health endpoint does not require authentication.

## Docker Compose

The repository also includes a Docker Compose configuration.

Start the API service with:

```bash
docker compose up --build
```

Stop the service with:

```bash
docker compose down
```

The API will be available at:

```text
http://localhost:8000
```

Configure required environment variables through your local environment or `.env` file.

Do not commit API keys or other secrets to source control.

See [Project Deployment](../07.%20projects/07.4%20deployment) for more information.

## API Authentication

Protected BindAI API endpoints use an API key.

Configure:

```text
BINDAI_API_KEY=your-secret-key
```

Then authenticate requests using:

```http
Authorization: Bearer your-secret-key
```

The `/health` endpoint is public.

Resource endpoints require authentication.

The v0.1 API uses a simple environment-based API key. Persistent API-key management and more advanced authentication are planned for future releases.

## Background Execution

BindAI v0.1 provides background automation execution through the automation worker.

Background runs can be submitted through the REST API and queried by run ID.

The v0.1 implementation uses in-process execution.

Distributed queue-based workers are planned for a future release and are not required for the v0.1 release.

The repository contains multiple BindAI packages under:


## Install uv

If `uv` is not already installed, install it with:

```bash
python -m pip install uv
```

Verify the installation:

```bash
uv --version
```

## Synchronize the Development Workspace

From the repository root, run:

```bash
uv sync
```

This synchronizes the workspace dependencies and creates or updates the development virtual environment.

## Activate the Development Environment

### Windows PowerShell

```powershell
.\.venv\Scripts\Activate.ps1
```

### macOS / Linux

```bash
source .venv/bin/activate
```

After activation, your terminal should display the active environment.

## Verify the Source Installation

Verify that Python is using the workspace environment:

```bash
python -c "import sys; print(sys.executable)"
```

Then verify the BindAI package:

```bash
python -c "import bindai; print('BindAI import OK')"
```

Expected output:

```text
BindAI import OK
```

Finally, verify the CLI:

```bash
bindai version
```

## Important: Do Not Use Root-Level Editable Installation

Because the BindAI repository is a multi-package `uv` workspace, **do not run**:

```bash
pip install -e .
```

from the repository root.

Use:

```bash
uv sync
```

instead.

Individual BindAI packages are located under:

```text
packages/
```

and are managed together through the workspace configuration.

This keeps workspace dependencies consistent across the repository.

## Development Workflow

When working on BindAI from source, a typical workflow is:

```bash
git pull
uv sync
```

Activate the environment if necessary.

### Windows PowerShell

```powershell
.\.venv\Scripts\Activate.ps1
```

### macOS / Linux

```bash
source .venv/bin/activate
```

Then run the test suite or work on the relevant package.

Run the main test suite with:

```bash
uv run pytest tests -q
```

To test an individual package:

```bash
uv run pytest packages/bindai-api/tests -q
```

BindAI uses a modular package structure, so changes to one package can be developed and tested independently while still being synchronized through the workspace.

## Updating BindAI

To upgrade the published PyPI package:

```bash
python -m pip install --upgrade bindai
```

Then verify the installed version:

```bash
bindai version
```

To upgrade optional packages:

```bash
python -m pip install --upgrade bindai-api bindai-connections
```

If you are developing from the source repository, update the repository and synchronize the workspace:

```bash
git pull
uv sync
```

## Common Issues

### `ModuleNotFoundError`

Make sure the correct environment is activated.

For source development, activate the workspace environment.

#### Windows PowerShell

```powershell
.\.venv\Scripts\Activate.ps1
```

#### macOS / Linux

```bash
source .venv/bin/activate
```

Then verify:

```bash
python -c "import bindai; print('BindAI import OK')"
```

### CLI Not Found

If the `bindai` command is unavailable after installation, make sure the environment containing BindAI is activated.

For source development, activate the `.venv` created by `uv sync`.

You can also verify which Python executable is being used:

```bash
python -c "import sys; print(sys.executable)"
```

Then verify:

```bash
bindai version
```

### Missing API Key

If a provider reports an authentication error, verify that the required environment variable is configured.

For example:

```text
OPENAI_API_KEY=your_api_key_here
```

Make sure the variable is available to the environment in which BindAI is running.

If you use a `.env` file, ensure it is located where your application expects it and that your application loads environment variables appropriately.

### Unsupported Python Version

Check your Python version:

```bash
python --version
```

BindAI v0.1 requires **Python 3.12 or newer**.

### Provider Configuration Issues

If your application cannot connect to a language model:

1. Verify that the required API key or local provider configuration is available.
2. Confirm the selected provider.
3. Confirm that the selected model is supported by that provider.
4. Run:

```bash
bindai doctor
```

5. Check the provider-specific documentation for additional configuration requirements.

Current provider integrations include:

- OpenAI
- Anthropic
- Google Gemini
- Groq
- Ollama
- OpenRouter

### Workspace Installation Issues

If source dependencies appear to be missing or inconsistent, run:

```bash
uv sync
```

Make sure the command is executed from the BindAI repository root.

Avoid installing the entire repository with:

```bash
pip install -e .
```

The repository is managed as a multi-package workspace.

### Docker Issues

If the Docker API container does not start:

1. Verify Docker is installed and running.
2. Build the image again:

```bash
docker build -t bindai-api .
```

3. Verify that port `8000` is available.
4. Make sure `BINDAI_API_KEY` is configured when running the container.

For Docker Compose:

```bash
docker compose up --build
```

To stop the service:

```bash
docker compose down
```
