# First Agent

In BindAI, an **Agent** is a core building block for AI applications.

An agent can combine:

* A language model
* Instructions
* Tools
* Memory
* Knowledge
* Retrieval
* Middleware
* Event handling

into a reusable component.

Agents provide a consistent execution interface while allowing additional capabilities to be added as your application grows.

---

# Creating an Agent

The recommended way to configure an agent is with `AgentBuilder`.

```python
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .instructions("You are a helpful assistant.")
    .build()
)
```

The builder returns an `AssistantAgent` instance.

Run the agent:

```python
result = agent.run("Explain what BindAI is.")

print(result.output)
```

The `run()` method returns an `AgentResult`.

---

# Agent Builder

`AgentBuilder` provides a fluent API for configuring an agent.

```python
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .instructions("You are a helpful assistant.")
    .build()
)
```

Common builder methods include:

| Method            | Purpose                       |
| ----------------- | ----------------------------- |
| `.name()`         | Set the agent name            |
| `.model()`        | Set the model identifier      |
| `.provider()`     | Configure the model provider  |
| `.instructions()` | Configure agent instructions  |
| `.tools()`        | Add one or more tools         |
| `.memory()`       | Configure memory              |
| `.knowledge()`    | Configure knowledge           |
| `.retriever()`    | Configure retrieval           |
| `.middleware()`   | Configure middleware          |
| `.events()`       | Configure the agent event bus |
| `.build()`        | Create the configured agent   |

The builder makes it possible to configure an agent incrementally without constructing every component manually.

---

# Configuring a Provider

A provider can be configured explicitly with `provider()`.

```python
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .name("assistant")
    .provider(
        "openai",
        model="gpt-4.1-mini",
    )
    .instructions("You are a helpful assistant.")
    .build()
)
```

Alternatively, the model can be configured using the provider-prefixed model format:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .instructions("You are a helpful assistant.")
    .build()
)
```

The provider configuration can also accept provider-specific options such as an API key, endpoint, or organization.

# Sending Prompts

The primary execution method is `run()`.

```python
result = agent.run(
    "Explain dependency injection."
)
```

The returned object is an `AgentResult`.

```python
print(result.output)
```

The `run()` method accepts an optional output type for structured responses.

```python
result = agent.run(
    "Generate a fictional person.",
    output=Person,
)
```

---

# Structured Output

BindAI can request structured output using a Python type.

For example, a Pydantic model can define the expected structure:

```python
from pydantic import BaseModel


class Person(BaseModel):
    name: str
    age: int
```

Pass the type to `run()`:

```python
result = agent.run(
    "Generate a fictional person.",
    output=Person,
)

print(result.output)
```

The model response is converted to the requested output type when supported by the configured provider.

---

# Streaming

Agents also expose a streaming interface.

```python
stream = agent.stream(context)
```

The `stream()` method operates with a BindAI `ExecutionContext` and is intended for applications that need incremental execution output.

For conversational streaming, BindAI also provides:

```python
agent.stream_chat(
    "Explain neural networks."
)
```

Use streaming when your application needs to process model output incrementally, such as interactive interfaces or long-running responses.

---

# Chat

Agents provide a dedicated `chat()` interface:

```python
result = agent.chat(
    "Explain neural networks."
)

print(result.output)
```

`chat()` accepts the same optional structured-output type as `run()`.

# Adding Tools

Tools allow an agent to perform actions through Python functions or other tool implementations.

A tool can be attached directly to an agent:

```python
agent.tool(my_tool)
```

Multiple tools can be added independently:

```python
agent.tool(weather_tool)
agent.tool(search_tool)
```

The equivalent `add_tool()` method is also available:

```python
agent.add_tool(weather_tool)
```

Tools can also be configured through the builder:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .tools(weather_tool, search_tool)
    .instructions("You are a helpful assistant.")
    .build()
)
```

The agent can then use the registered tools during execution when supported by the configured model provider.

---

# Adding Memory

Memory can be attached through the builder:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .memory(memory)
    .instructions("You are a helpful assistant.")
    .build()
)
```

Memory can also be attached after an agent has been created:

```python
agent.use_memory(memory)
```

The exact memory implementation depends on the configured memory provider.

---

# Adding Knowledge

Knowledge can be configured through the builder:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .knowledge(knowledge)
    .instructions("Answer questions using the available knowledge.")
    .build()
)
```

Knowledge can also be attached directly:

```python
agent.use_knowledge(knowledge)
```

Knowledge integrations can be used to provide application-specific information to an agent.

---

# Adding a Retriever

Retrieval can be configured through the builder:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .retriever(retriever)
    .instructions("Use retrieved information when answering questions.")
    .build()
)
```

An existing agent can also receive a retriever:

```python
agent.use_retriever(retriever)
```

Retrievers can be used as part of knowledge and RAG architectures.

---

# Middleware

Middleware can be configured through the builder:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .middleware(middleware)
    .instructions("You are a helpful assistant.")
    .build()
)
```

Middleware can also be attached to an existing agent:

```python
agent.use_middleware(middleware)
```

Middleware is useful for cross-cutting application behavior such as:

* Logging
* Metrics
* Authentication
* Request processing
* Output processing

The specific behavior depends on the middleware implementation.

---

# Event Handling

BindAI agents expose event-related APIs for observing execution.

An event bus can be supplied through the builder:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .events(event_bus)
    .instructions("You are a helpful assistant.")
    .build()
)
```

Agents also expose event and lifecycle methods including:

```python
agent.on(...)
agent.hook(...)
agent.before_run(...)
agent.after_run(...)
agent.on_error(...)
```

These APIs can be used to integrate application-specific monitoring, lifecycle handling, and execution behavior.

# Loading an Agent from a Project

`AgentBuilder` provides `from_project()` for project-based configuration.

```python
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .from_project()
    .build()
)
```

Project-based configuration allows agent settings to be managed outside the Python source code.

The exact configuration available depends on the project's configuration files and components.

---

# Multi-Provider Configuration

BindAI's builder supports provider configuration independently from the rest of the agent application.

For example:

```python
AgentBuilder().model("openai:gpt-4.1-mini")
```

or:

```python
AgentBuilder().provider(
    "openai",
    model="gpt-4.1-mini",
)
```

The same builder structure can be used when configuring other supported providers.

Provider-specific configuration can be supplied through `provider()` when required:

```python
AgentBuilder().provider(
    "openai",
    api_key="your_api_key",
    model="gpt-4.1-mini",
)
```

Keep provider credentials outside source code whenever possible. Environment variables or other secure configuration mechanisms are recommended.

---

# Direct Agent Construction

The `Agent` class is also publicly available:

```python
from bindai import Agent
```

Its constructor accepts:

```python
Agent(
    name="assistant",
    provider=provider,
    instructions="You are a helpful assistant.",
)
```

The `Agent` constructor expects a configured provider object rather than a model string.

For most application code, `AgentBuilder` is the recommended approach because it provides a convenient interface for configuring models, providers, tools, memory, knowledge, retrieval, middleware, and events.

---

# Agent Execution

The basic execution flow is:

1. Configure an agent.
2. Build the agent.
3. Send a message.
4. BindAI executes the agent.
5. The agent may use configured tools or other capabilities.
6. An `AgentResult` is returned.

For a basic application:

```python
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .instructions("You are a helpful assistant.")
    .build()
)

result = agent.run(
    "What is BindAI?"
)

print(result.output)
```

This provides the foundation for adding tools, memory, knowledge, retrieval, middleware, and workflows as the application grows.
