# Knowledge Overview

Knowledge enables BindAI agents to retrieve information from external sources instead of relying only on the language model's built-in knowledge.

By connecting documents, databases, APIs, or other information sources, agents can answer questions using accurate, up-to-date, and organization-specific data.

Knowledge is the foundation of Retrieval-Augmented Generation (RAG).

---

# What is Knowledge?

Knowledge represents information that exists outside the language model.

Examples include:

- company documentation
- PDF files
- Markdown documentation
- product manuals
- internal wikis
- databases
- REST APIs
- websites
- cloud storage

Instead of memorizing this information, the agent retrieves only the relevant pieces during execution.

---

# Why Use Knowledge?

Language models have several limitations:

- training data eventually becomes outdated
- they cannot access private company information
- they do not automatically know your documentation
- they may hallucinate when information is missing

Knowledge solves these problems by supplying reliable context before the model generates its response.

---

# How Retrieval-Augmented Generation Works

Retrieval-Augmented Generation (RAG) combines document retrieval with language model generation.

Instead of asking the model to answer from memory alone, BindAI first searches the connected knowledge source.

```text
User Question

↓

Knowledge Retrieval

↓

Relevant Documents

↓

Language Model

↓

Final Response
```

The retrieved information becomes part of the prompt sent to the model.

---

# Example

Imagine your company has an employee handbook.

The user asks:

```text
What is our vacation policy?
```

Instead of guessing, the agent:

1. searches the handbook
2. retrieves the relevant section
3. includes it in the model request
4. generates an answer based on the retrieved content

This produces answers grounded in your own documentation.

# Retrieval Instead of Loading Everything

Large collections of documents should not be sent entirely to the language model.

Instead, BindAI retrieves only the most relevant content.

```text
Question

↓

Retriever

↓

Top Matches

↓

Language Model
```

This approach:

- reduces prompt size
- improves response quality
- lowers token usage
- scales to very large document collections

---

# Semantic Search

Modern retrieval systems typically use embeddings instead of keyword matching.

Semantic search understands meaning rather than exact wording.

For example:

User asks:

```text
How do I reset my password?
```

The document might contain:

```text
Account credential recovery
```

Even though the wording differs, semantic search can still retrieve the correct document.

---

# Knowledge and the Execution Pipeline

Knowledge retrieval occurs before the language model generates a response.

A simplified execution pipeline looks like this:

```text
User Input

↓

Retrieve Knowledge

↓

Build Prompt

↓

Language Model

↓

Response
```

If no relevant information is found, the agent continues using only the existing prompt and conversation context.

---

# Knowledge vs Memory

Knowledge and Memory serve different purposes.

| Knowledge | Memory |
| ---------- | ------ |
| External information | Conversation history |
| Shared across users | Usually user-specific |
| Mostly static | Continuously updated |
| Documents and datasets | Previous interactions |
| Organization knowledge | Personal context |

Use Knowledge to answer factual questions.

Use Memory to remember previous conversations.

---

# Knowledge vs Workflow Variables

Workflow variables exist only during execution.

Knowledge exists independently of workflows.

| Workflow Variables | Knowledge |
| ------------------ | --------- |
| Temporary | Persistent |
| Runtime state | External information |
| Created during execution | Exists before execution |
| Shared between workflow nodes | Shared across many executions |

---

# Using Knowledge with Agents

Knowledge can be attached directly to an agent.

```python
agent.use_knowledge(
    knowledge,
)
```

Once configured, BindAI automatically performs retrieval whenever the agent executes.

No additional retrieval logic is required inside the application.

---

# Using Knowledge in Workflows

Knowledge retrieval also integrates naturally into workflows.

```text
Start

↓

Retrieve Knowledge

↓

Agent

↓

Decision

↓

Next Step
```

Retrieved information becomes available to downstream workflow steps.

---

# Best Practices

- Keep documents organized and well structured.
- Use retrieval instead of loading complete document collections.
- Remove outdated or duplicated content.
- Separate Knowledge from Memory.
- Prefer semantic search for large datasets.
- Keep retrieved context concise.
- Regularly update knowledge sources.

# Summary

Knowledge allows BindAI agents to answer questions using information stored outside the language model.

By retrieving only the most relevant content before generation, agents can produce accurate, current, and organization-specific responses while remaining scalable and efficient.
