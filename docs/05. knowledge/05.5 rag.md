# Retrieval-Augmented Generation (RAG)

Retrieval-Augmented Generation (RAG) combines information retrieved from an external knowledge source with language-model generation.

In BindAI V1, the implemented Knowledge flow allows an agent to use project-local Knowledge during execution.

The V1 flow is:

```text
User Input
    |
    v
Agent
    |
    v
Configured Knowledge
    |
    v
Knowledge Search
    |
    v
Relevant Knowledge
    |
    v
Agent / Model
    |
    v
Response
```

BindAI V1 does not expose a separate configurable vector-RAG pipeline. Knowledge retrieval is integrated into the agent runtime.

---

# What Is RAG?

RAG has two basic parts:

1. **Retrieval** — finding relevant information from an external knowledge source.
2. **Generation** — using that information during model execution.

A simplified flow is:

```text
User Question
      |
      v
Knowledge Search
      |
      v
Relevant Information
      |
      v
Agent
      |
      v
Language Model
      |
      v
Response
```

The purpose is to allow the agent to use project information that is not contained directly in the user's request.

---

# BindAI V1 RAG Architecture

The implemented BindAI V1 architecture is intentionally simple:

```text
Project Knowledge
       |
       v
Knowledge Search
       |
       v
Relevant Content
       |
       v
Agent
       |
       v
Model
       |
       v
Response
```

Knowledge is configured on the agent.

The workflow does not need a separate `Retriever` or `RAG` node.

---

# Project Knowledge

RAG in V1 uses project-local Knowledge.

For example:

```text
my-project/
├── agents/
├── knowledge/
│   └── knowledge-test.md
├── tools/
└── workflows/
```

An agent can be configured to use a Knowledge source such as:

```text
knowledge-test
```

During execution, the Knowledge runtime searches that configured source.

---

# Agent Knowledge Integration

The main V1 integration point is the Agent.

Conceptually:

```text
Agent
 |
 +-- Memory
 |
 +-- Knowledge
 |
 +-- Model
```

Knowledge provides reference information during agent execution.

The Agent remains responsible for the model interaction and final response.

---

# Concrete V1 Example

Suppose a project contains a Knowledge document with:

```text
ORANGE-PENGUIN-742
```

The project has a Knowledge source named:

```text
knowledge-test
```

An agent is configured to use:

```text
knowledge-test
```

A workflow can then execute that agent.

```text
Start
  |
  v
Agent
  |
  |-- Knowledge: knowledge-test
  |
  v
End
```

When the agent receives a request that requires information from the configured Knowledge source, BindAI searches the Knowledge source during execution.

The retrieved information can include:

```text
ORANGE-PENGUIN-742
```

The agent can then use that information as part of its model execution.

---

# Two-Run Example

The same Knowledge configuration can be used across separate workflow runs.

## Run 1

```text
Workflow
   |
   v
Agent
   |
   v
knowledge-test
   |
   v
Knowledge Search
   |
   v
ORANGE-PENGUIN-742
```

The first execution can retrieve the known value from the project Knowledge.

## Run 2

The workflow is executed again with another request requiring information from the same Knowledge source.

```text
Workflow
   |
   v
Agent
   |
   v
knowledge-test
   |
   v
Knowledge Search
   |
   v
Relevant Knowledge
```

The Knowledge source is resolved again for the new execution.

This demonstrates the important V1 behavior: Knowledge is a runtime project resource used by the configured agent rather than information that must be manually copied into every workflow input.

---

# RAG and Workflows

RAG is not a separate workflow node in V1.

Instead, Knowledge is used through an Agent node.

For example:

```text
Start
  |
  v
Agent
  |
  |-- configured Knowledge
  |
  v
Tool
  |
  v
End
```

The workflow controls the execution sequence.

The Agent controls its Knowledge usage.

This means Knowledge can participate in larger workflows without introducing a separate RAG-specific node.

---

# RAG and Memory

Memory and Knowledge serve different purposes.

| Memory                                         | Knowledge                              |
| ---------------------------------------------- | -------------------------------------- |
| Retains conversation/application context       | Provides project reference information |
| Persisted through the configured memory system | Stored as project Knowledge            |
| Used across agent executions                   | Searched during agent execution        |
| Focused on retained context                    | Focused on reference information       |

An agent can use both:

```text
             Agent
                |
        +-------+-------+
        |               |
        v               v
     Memory          Knowledge
        |               |
        v               v
 Retained Context   Retrieved Context
        |               |
        +-------+-------+
                |
                v
              Model
```

They should not be treated as the same storage mechanism.

---

# RAG and Tools

Tools execute operations.

Knowledge provides reference information.

```text
Tool
 |
 +-- Call an API
 +-- Send a message
 +-- Perform an action


Knowledge
 |
 +-- Search project information
 +-- Provide reference content
```

An agent can use both in the same workflow.

For example:

```text
Start
  |
  v
Agent
  |
  +---- Knowledge
  |
  v
Tool
  |
  v
End
```

A Knowledge source can provide information while a Tool performs an external operation.

---

# RAG and Connections

BindAI V1 also supports Webhook connections through connection-backed tools.

A connection is an execution mechanism, not a Knowledge retriever.

The distinction is:

```text
Knowledge
    |
    +-- Retrieve project reference information


Webhook Connection Tool
    |
    +-- Send data to an external HTTP endpoint
```

An agent or workflow can use both when an application needs project Knowledge together with an external operation.

---

# RAG and Workflow Control Flow

Knowledge-backed agents can participate in the V1 workflow control-flow features.

For example:

```text
Start
  |
  v
Agent
  |
  v
Condition
  |
  +---- true ----> Tool
  |
  +---- false ---> Human Task
```

The Agent can use configured Knowledge before the workflow continues to the next node.

Knowledge therefore complements, rather than replaces, workflow control flow.

---

# Knowledge Retrieval

The V1 retrieval path is:

```text
Configured Agent
       |
       v
Knowledge Source
       |
       v
Search
       |
       v
Relevant Content
```

V1 does not require the workflow author to manually implement this search step.

The Knowledge configuration identifies the project information available to the agent.

---

# What V1 Does Not Implement

The following broader RAG capabilities are **not exposed as BindAI V1 Studio features**:

* Configurable vector retrieval
* BM25 retrieval configuration
* Hybrid retrieval configuration
* Embedding-model configuration for Knowledge retrieval
* Metadata-filtered retrieval
* Configurable reranking
* Conversational retrieval configuration
* Top-K retrieval controls
* Vector-database configuration
* RAG-specific workflow nodes
* Knowledge ingestion pipelines
* Configurable chunking pipelines
* External retrieval-provider configuration

These are common components in larger RAG systems, but they should not be confused with the implemented V1 Knowledge runtime.

---

# RAG and Model Providers

The model still comes from the agent's configured model/provider.

Knowledge retrieval does not replace the model.

The execution relationship is:

```text
Knowledge
    |
    v
Retrieved Information
    |
    v
Agent
    |
    v
Configured Model Provider
    |
    v
Response
```

The Knowledge layer provides information; the model generates the response.

---

# RAG Limitations

Retrieval does not guarantee that a generated response is correct.

Possible issues include:

* The relevant Knowledge may not contain the requested information.
* The search may not find the required content.
* Retrieved information may be incomplete.
* The model may misunderstand retrieved information.
* The model may produce information not supported by the retrieved content.

Applications should therefore treat Knowledge as supporting context rather than as a guarantee of factual correctness.

# Testing Knowledge-Backed RAG

A simple V1 test uses a known value in project Knowledge.

For example:

```text
Knowledge:
knowledge-test

Known content:
ORANGE-PENGUIN-742
```

Then:

1. Configure an agent to use `knowledge-test`.
2. Execute a workflow containing that agent.
3. Use a request that requires the stored information.
4. Verify that the agent can access the Knowledge content.
5. Execute the workflow again to verify that the Knowledge configuration works across separate runs.

This tests the actual V1 path:

```text
Project Knowledge
       |
       v
Agent Configuration
       |
       v
Runtime Search
       |
       v
Agent Execution
```

# RAG in Studio

Studio provides the V1 pieces needed to create a Knowledge-backed agent:

1. Manage project Knowledge.
2. Configure Knowledge for an agent.
3. Place the agent in a workflow.
4. Execute the workflow.
5. Inspect the resulting execution.

The Studio workflow editor does not require a separate RAG node.

---

# RAG and API Execution

Knowledge-backed workflows can also be executed through the Studio API.

The workflow execution remains the same:

```text
API Request
    |
    v
Workflow
    |
    v
Agent
    |
    v
Configured Knowledge
    |
    v
Model
    |
    v
Workflow Result
```

The API therefore executes the same project runtime used by Studio.

---

# Current V1 RAG Scope

The implemented V1 foundation consists of:

* Project-local Knowledge
* Knowledge management in Studio
* Agent Knowledge configuration
* Runtime Knowledge search
* Knowledge-backed Agent execution
* Knowledge use inside workflows
* Compatibility with Memory
* Compatibility with Tools
* Compatibility with Webhook connection-backed Tools
* API workflow execution

V1 deliberately does not expose a full configurable RAG pipeline.

---

# Summary

BindAI V1 supports a practical Knowledge-backed generation flow:

```text
Project Knowledge
       |
       v
Knowledge Search
       |
       v
Relevant Information
       |
       v
Agent
       |
       v
Language Model
       |
       v
Response
```

The key V1 integration is between **Knowledge and Agents**.

Knowledge supplies project reference information during agent execution, while workflows provide the surrounding execution and control-flow structure.

Advanced RAG components such as vector retrieval, BM25, hybrid search, embeddings configuration, reranking, and configurable ingestion pipelines are not part of the documented V1 Studio surface.
