# Retrievers

A **Retriever** is responsible for finding the most relevant information from a knowledge source before the language model generates a response.

Instead of searching every document manually or sending an entire knowledge base to the model, the retriever identifies only the information that is most useful for answering the user's question.

Retrievers are one of the core components of Retrieval-Augmented Generation (RAG).

---

# What is a Retriever?

A retriever receives a query and returns the most relevant documents or document chunks.

Conceptually:

```text
User Question

↓

Retriever

↓

Relevant Documents
```

Those documents are then added to the prompt that is sent to the language model.

---

# Why Retrievers?

Modern knowledge bases can contain thousands—or even millions—of documents.

Language models have limited context windows, so including everything is impossible.

Instead:

```text
Knowledge Base

↓

Retriever

↓

Most Relevant Results

↓

Language Model
```

Only the information related to the user's question is included.

---

# Retrieval Pipeline

A typical retrieval pipeline looks like this.

```text
User Question

↓

Query Processing

↓

Retriever

↓

Top Matching Documents

↓

Prompt Construction

↓

Language Model

↓

Final Response
```

This process happens automatically during agent execution.

---

# Retriever Responsibilities

A retriever typically performs the following tasks:

- receive a user query
- search the knowledge source
- rank candidate results
- filter irrelevant content
- return the most useful documents

The exact implementation depends on the retrieval strategy being used.

---

# Example

Imagine a knowledge base containing:

```text
Installation Guide

API Reference

Authentication Guide

Troubleshooting Guide
```

The user asks:

```text
How do I reset my password?
```

The retriever may return:

```text
Authentication Guide

Password Recovery
```

Only those sections are passed to the language model.

---

# Top-K Retrieval

Most retrievers return only the **K** highest-ranking results.

```text
Search Results

↓

1

2

3

4

5

↓

Top 3 Returned
```

Choosing the appropriate value for **K** helps balance:

- response quality
- prompt size
- token usage
- retrieval speed

---

# Metadata Filtering

Retrievers can filter documents using metadata before ranking them.

Examples include:

```text
Category = Documentation

Version = 2.0

Language = English
```

Metadata filtering reduces noise and improves retrieval accuracy.

---

# Semantic Retrieval

Many modern retrievers perform semantic search using embeddings.

Instead of matching exact words, semantic retrieval compares meaning.

Example:

User asks:

```text
How do I recover my account?
```

The documentation contains:

```text
Password reset procedure
```

Although the wording differs, semantic retrieval can still identify the correct document.

---

# Hybrid Retrieval

Some applications combine multiple retrieval techniques.

```text
Keyword Search

+

Semantic Search

↓

Combined Ranking
```

Hybrid retrieval often provides better results by combining exact keyword matching with semantic similarity.

---

# Custom Retrievers

BindAI allows you to implement your own retrieval strategy.

Examples include:

- SQL database search
- Elasticsearch
- OpenSearch
- enterprise search engines
- REST APIs
- graph databases
- cloud search services

As long as the retriever follows the expected interface, it can be used by any agent.

---

# Using a Retriever

Attach a retriever to an agent.

```python
agent.use_retriever(
    retriever,
)
```

Whenever the agent executes, the retriever automatically searches for relevant context before the model generates a response.

---

# Retriever vs Knowledge

Knowledge stores information.

Retrievers search that information.

| Knowledge | Retriever |
| ---------- | --------- |
| Stores documents | Finds documents |
| Persistent | Runtime component |
| Repository | Search engine |
| Data | Retrieval logic |

Knowledge and retrievers work together to build an effective RAG system.

---

# Performance Considerations

Retriever performance depends on factors such as:

- embedding quality
- search algorithm
- vector database performance
- document chunk size
- metadata filtering
- ranking strategy

Good retrieval quality is often more important than simply increasing the size of the knowledge base.

---

# Best Practices

- Retrieve only the most relevant documents.
- Keep **Top-K** relatively small.
- Use metadata filtering whenever possible.
- Prefer semantic retrieval for natural language questions.
- Consider hybrid retrieval for better accuracy.
- Rank results before sending them to the language model.
- Monitor retrieval quality as your knowledge base grows.

---

# Summary

Retrievers connect language models with external knowledge by selecting only the information that is most relevant to a user's question.

By retrieving a small, high-quality set of documents instead of an entire knowledge base, retrievers improve response accuracy, reduce token usage, and enable BindAI agents to scale to large collections of external information.
