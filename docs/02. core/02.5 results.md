# Results

Every execution in BindAI returns a **result object**.

Instead of returning raw strings or provider-specific responses, BindAI returns structured result types that expose the execution status, output, usage information, and any errors.

This consistent API makes it easy to build production applications without depending on the response format of a specific AI provider.

---

# Why Results?

Returning structured results provides several advantages:

- Consistent API across all providers
- Predictable error handling
- Structured output support
- Easier debugging
- Future compatibility
- Provider independence

Whether you're using OpenAI, Ollama, or another provider, your application interacts with the same result object.

---

# AgentResult

Every agent execution returns an `AgentResult`.

```python
result = agent.run(
    "Explain what BindAI is."
)

print(result)
```

Typical output:

```python
AgentResult(
    success=True,
    output="BindAI is an open-source framework for building AI agents.",
    error=None,
)
```

---

# Accessing the Response

The generated response is available through `output`.

```python
result = agent.run(
    "Hello!"
)

print(result.output)
```

Output

```text
Hello! How can I help you today?
```

---

# Success State

Every result indicates whether execution completed successfully.

```python
if result.success:
    print(result.output)
```

Using `success` is recommended instead of assuming every execution succeeded.

---

# Error Handling

When something goes wrong, BindAI returns a failed result.

```python
result = agent.run(
    "Hello"
)

if not result.success:
    print(result.error)
```

Example

```python
AgentResult(
    success=False,
    output=None,
    error="OpenAI authentication failed."
)
```

Most operational failures are returned through the result object rather than raising exceptions.

---

# Structured Output

BindAI can automatically convert model responses into structured Python objects.

```python
from pydantic import BaseModel


class Person(BaseModel):
    name: str
    age: int


result = agent.run(
    "Generate a fictional person.",
    output=Person,
)

print(result.output)
```

Output

```python
Person(
    name="Alice",
    age=27,
)
```

This eliminates manual JSON parsing.

---

# Workflow Results

Workflow execution also returns a result object.

```python
result = workflow.run()
```

The workflow output contains the variables produced during execution.

```python
print(result.output)
```

Example

```python
{
    "summary": "...",
    "approved": True,
}
```

---

# Tool Results

Tools return structured results internally.

```python
ToolResult(
    success=True,
    output="Search completed.",
    error=None,
)
```

This allows agents and workflows to process tool responses consistently.

---

# Human Approval Results

Human approval steps also expose structured results.

Example

```python
{
    "approved": True,
    "comment": "Looks good."
}
```

Workflow execution resumes using these values.

---

# Common Pattern

Most BindAI components follow the same result model.

```text
Execution

↓

Result

├── success
├── output
└── error
```

This consistency makes it easy to combine agents, workflows, tools, and custom components.

---

# Results vs Exceptions

BindAI distinguishes between expected execution failures and programming errors.

Result objects represent operational failures such as:

- Provider authentication failures
- Timeout errors
- Model validation failures
- Tool execution failures

Python exceptions are generally reserved for:

- Invalid framework configuration
- Missing dependencies
- Programming mistakes
- Internal framework errors

---

# Debugging

During development it's useful to inspect the full result.

```python
print(result.success)
print(result.output)
print(result.error)
```

Because every provider returns the same structure, debugging remains consistent regardless of which model you're using.

---

# Best Practices

- Always check `success` before using `output`.
- Log `error` values in production.
- Prefer structured output over manual JSON parsing.
- Return consistent result objects from custom tools.
- Avoid exposing provider-specific responses to application code.
- Keep application logic dependent on `AgentResult`, not individual providers.

---

# Summary

`AgentResult` provides a stable interface for AI execution throughout BindAI.

Whether you're running an agent, executing a workflow, or calling tools, the same predictable result structure makes applications easier to build, test, and maintain.
