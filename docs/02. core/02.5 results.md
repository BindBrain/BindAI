# Results

BindAI returns structured result objects from agent execution instead of exposing provider-specific response objects directly.

The result gives your application a consistent way to access the generated output and execution information.

---

# AgentResult

Calling `agent.run()` returns an `AgentResult`.

```python
result = agent.run("Explain what BindAI is.")

print(result.output)
```

The `AgentResult` is the primary result type returned by agent execution.

You can inspect the result during development:

```python
print(result)
```

For the exact fields available in your installed BindAI version, inspect the result type directly:

```python
from bindai import AgentResult
import inspect

print(inspect.signature(AgentResult))
print(AgentResult.__annotations__)
```

This is useful when working with a particular BindAI release because result details can evolve as the framework develops.

---

# Accessing the Output

The generated response is available through `result.output`.

```python
result = agent.run("What is BindAI?")

print(result.output)
```

Example:

```text
BindAI is an open-source Python framework for building AI applications.
```

For normal text generation, `output` contains the generated response.

When structured output is requested, `output` contains the resulting Python object.

---

# Structured Output

BindAI supports validated structured output through the `output` parameter.

```python
from pydantic import BaseModel
from bindai import Agent


class Person(BaseModel):
    name: str
    age: int


agent = Agent(
    provider="openai",
    name="person-generator",
    instructions="Generate fictional people.",
)

result = agent.run(
    "Generate a fictional person.",
    output=Person,
)

print(result.output)
```

The returned output can be used as a validated `Person` instance rather than requiring manual JSON parsing.

---

# Inspecting Result Information

During development, inspect the result object directly.

```python
result = agent.run("Hello!")

print(result)
print(result.output)
```

If your application needs additional result metadata, inspect the installed `AgentResult` type:

```python
from bindai import AgentResult

print(AgentResult.__annotations__)
```

This approach keeps documentation and application code aligned with the version of BindAI being used.

---

# Handling Execution Failures

Agent execution can fail for different reasons, including provider configuration problems, authentication failures, invalid model configuration, or errors during execution.

Do not assume that every failure is represented by a particular result field. Handle failures according to the behavior of the specific BindAI version and provider configuration.

For development, inspect the exception or result returned by the failing operation:

```python
try:
    result = agent.run("Hello!")
    print(result.output)
except Exception as exc:
    print(f"Agent execution failed: {exc}")
```

For production applications, catch specific exception types when your application needs to distinguish between different failure categories.

---

# Tool Results

Tools are separate from `AgentResult`.

A tool can return ordinary Python values:

```python
from bindai import tool


@tool
def add(a: int, b: int):
    return a + b
```

The tool result is then made available to the agent execution pipeline.

For more advanced tool execution and result handling, use the Tool API rather than treating tool results as identical to `AgentResult`.

---

# Workflow Results

Workflows have their own execution model and result handling.

A workflow can produce values that are passed between workflow nodes and eventually exposed as workflow output.

For example:

```python
result = workflow.run()

print(result)
```

The exact workflow result structure depends on the workflow implementation and the version of BindAI being used.

When working with workflow results programmatically, inspect the returned object:

```python
print(type(result))
print(result)
```

This is preferable to assuming that every workflow result has the same fields as `AgentResult`.

---

# Result Flow

The general execution model can be represented as:

```text
Agent Execution
      │
      ▼
  AgentResult
      │
      ├── output
      │
      └── execution information
```

The exact information available on the result depends on the BindAI version and the type of execution.

---

# Results and Exceptions

Result objects and Python exceptions serve different purposes.

A result represents the outcome of an operation that completed and returned a result object.

Exceptions represent failures that interrupt normal execution.

For example:

```python
try:
    result = agent.run("Hello!")
except Exception as exc:
    print(exc)
else:
    print(result.output)
```

This distinction is important when building production applications. Do not assume that every possible failure will be converted into an `AgentResult`.

---

# Debugging Results

During development, inspect the complete result and its type.

```python
result = agent.run("Explain dependency injection.")

print(type(result))
print(result)
print(result.output)
```

You can also inspect the result class:

```python
from bindai import AgentResult

print(AgentResult.__annotations__)
```

This is particularly useful when developing against a changing or locally installed version of BindAI.

---

# Best Practices

* Use `result.output` for the generated agent output.
* Use structured output when downstream code requires predictable Python objects.
* Inspect result types instead of assuming undocumented fields.
* Handle execution exceptions explicitly when failures need special treatment.
* Keep provider-specific response handling out of application code.
* Test result handling against the BindAI version used by your application.
* Treat `AgentResult` as the stable abstraction for agent execution rather than depending on provider SDK response objects.

---

# Summary

`AgentResult` is the result abstraction returned by BindAI agent execution.

For standard text generation, access the generated response through `result.output`. For structured generation, `output` can contain a validated Python object.

When building production applications, rely on the documented result API and inspect the installed result type when you need additional metadata or version-specific behavior.
