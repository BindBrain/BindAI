# Prompts

Prompts define how an AI agent behaves.

In BindAI, prompts are treated as reusable, structured objects rather than long hardcoded strings.

You can:

* Define prompts directly in Python
* Configure them in YAML
* Reuse them across multiple agents
* Inject runtime variables
* Build prompts dynamically

Keeping prompts separate from business logic makes AI applications easier to maintain and evolve.

---

# What is a Prompt?

A prompt contains the instructions that guide the language model.

The most important part is usually the **system prompt**, which defines:

* The agent's role
* Its behavior
* Writing style
* Constraints
* Expected output

Example:

```text id="t84ydm"
You are an experienced software architect.

Explain concepts clearly.

Keep responses concise.

Use practical examples whenever possible.
```

---

# Using Instructions

The simplest way to define a prompt is with the `instructions` parameter.

```python id="hqmvz2"
from bindai import Agent

agent = Agent(
    instructions="""
You are a helpful assistant.

Always answer politely.
"""
)
```

Internally, BindAI stores these instructions inside a `Prompt` object.

---

# Prompt Objects

For advanced scenarios, prompts can be managed explicitly.

```python id="vw2xsu"
from bindai_prompts import Prompt

prompt = Prompt()

prompt.system = """
You are an experienced Python developer.
"""

print(prompt.system)
```

This is useful when prompts need to be shared between multiple agents.

---

# Using a Prompt Object

```python id="qht5un"
from bindai import Agent
from bindai_prompts import Prompt

prompt = Prompt()

prompt.system = """
You are a helpful assistant.
"""

agent = Agent(
    prompt=prompt
)
```

This produces the same behavior as passing `instructions`, while making prompt reuse easier.

---

# YAML Prompts

Most production projects store prompts inside YAML.

Example:

```yaml id="ysyw4r"
name: assistant

provider: openai

model: gpt-4.1-mini

instructions: |
  You are a helpful assistant.

  Keep answers concise.

  Always explain your reasoning.
```

Load it directly.

```python id="8ybrd8"
from bindai import Agent

agent = Agent.from_yaml(
    "assistant.yaml"
)
```

Separating prompts from code allows prompt updates without modifying application logic.

# Prompt Variables

Prompts often need runtime values.

Instead of creating many similar prompts, inject variables.

Example template:

```text id="6i8k4g"
Summarize the following document.

{{document}}
```

At runtime:

```python id="e9im8y"
document = "Large document..."

result = agent.run(
    f"""
Summarize:

{document}
"""
)
```

Prompt templates remain reusable while application data changes dynamically.

---

# Static vs Dynamic Prompts

Static prompt:

```text id="54czkp"
You are a financial advisor.
```

Dynamic prompt:

```text id="rvm4bc"
You are a financial advisor.

Today's market data:

{{market}}
```

Static prompts define behavior.

Dynamic prompts combine behavior with runtime context.

---

# Prompt Composition

Large prompts are easier to maintain when organized into logical sections.

Instead of writing one long paragraph:

```text id="wgtqez"
Role

Goals

Rules

Output Format

Examples
```

This structure makes prompts easier to review and update.

---

# Output Instructions

Clearly describing the expected output improves consistency.

Markdown example:

```text id="jwx0n5"
Return your answer as Markdown.

Use headings and bullet points.
```

JSON example:

```text id="vhmvd7"
Return valid JSON only.
```

Table example:

```text id="scvhlh"
Return the result as a Markdown table.
```

Structured instructions generally produce more reliable outputs.

# Reusing Prompts

One prompt can be shared across multiple agents.

```python id="2mp8jg"
from bindai import Agent
from bindai_prompts import Prompt

prompt = Prompt()

prompt.system = """
You are a technical writer.
"""

writer = Agent(
    prompt=prompt
)

reviewer = Agent(
    prompt=prompt
)
```

Updating the prompt automatically affects every agent using it.

# Prompts and Conversation

Conversation history is separate from prompts.

```text id="8uxydo"
System Prompt

        +

Conversation History

        +

User Message

        =

Model Request
```

The prompt defines behavior.

The conversation provides context.

---

# Prompts and Memory

Memory is also separate from prompts.

```text id="bqv3hr"
Prompt

      +

Memory

      +

Conversation

      +

Current User Input

      =

Final Model Request
```

Each component has a different responsibility.

* Prompt defines behavior.
* Memory stores long-term information.
* Conversation stores recent interactions.

---

# Prompts and Knowledge (RAG)

Knowledge retrieval happens before generation.

```text id="wv6kjt"
Prompt

      +

Retrieved Documents

      +

Conversation

      =

Model Input
```

The prompt should explain **how** the agent should use retrieved knowledge—not contain the knowledge itself.

Example:

```text id="h8pj5z"
Answer questions using the retrieved documentation.

If the answer cannot be found, say so honestly.
```

# Prompt Organization

As projects grow, many teams organize prompts by domain.

Example:

```text id="7iyt5n"
prompts/

├── support.md
├── sales.md
├── onboarding.md
├── summarization.md
└── review.md
```

This keeps prompts discoverable and reusable across the project.

---

# Best Practices

* Keep prompts focused on one responsibility.
* Separate behavior from runtime data.
* Store production prompts in YAML.
* Reuse prompts whenever possible.
* Clearly define output formats.
* Avoid embedding large documents directly into prompts.
* Let knowledge retrieval provide factual context instead of expanding the system prompt.
* Review prompts regularly as your application evolves.
