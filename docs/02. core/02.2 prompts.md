# Prompts

Prompts define the instructions and behavior that guide BindAI agents.

At the simplest level, prompts can be provided directly through the agent's `instructions` parameter.

For larger applications, prompts can be separated from application logic and reused across multiple agents.

---

# What Is a Prompt?

A prompt provides the information and instructions an AI model needs to perform a task.

A system-style instruction can define:

* The agent's role
* Expected behavior
* Tone and style
* Constraints
* Output requirements
* Domain-specific rules

For example:

```text
You are an experienced software architect.

Explain concepts clearly.

Keep responses concise.

Use practical examples whenever possible.
```

---

# Using Instructions

The simplest way to configure an agent's behavior is with `instructions`.

```python
from bindai import Agent

agent = Agent(
    name="assistant",
    provider="openai",
    instructions="""
You are a helpful assistant.

Always answer clearly and politely.
""",
)
```

Instructions can also be configured through `AgentBuilder`:

```python
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .instructions("""
You are a helpful assistant.

Always answer clearly and politely.
""")
    .build()
)
```

The builder approach is useful when the agent has additional configuration such as tools, memory, knowledge, or middleware.

---

# Prompt Objects

BindAI's `Agent` constructor accepts an optional `prompt` argument.

```python
from bindai import Agent

agent = Agent(
    name="assistant",
    provider="openai",
    prompt=prompt,
)
```

A prompt object can be useful when prompt configuration needs to be represented separately from the agent itself.

The exact prompt-object API depends on the BindAI prompt package being used.

---

# Keeping Prompts Separate from Application Logic

For larger applications, avoid putting large instruction blocks throughout application code.

Instead, keep prompt definitions in dedicated files or modules.

For example:

```text
prompts/
├── support.md
├── sales.md
├── onboarding.md
├── summarization.md
└── review.md
```

This makes prompts easier to:

* Review
* Version
* Test
* Reuse
* Update independently from application logic

The exact loading mechanism depends on how your project manages prompt resources.

---

# Static Instructions

A static instruction remains the same for every execution.

```python
agent = (
    AgentBuilder()
    .name("writer")
    .model("openai:gpt-4.1-mini")
    .instructions("""
You are a technical writer.

Use clear language.

Prefer concise explanations.
""")
    .build()
)
```

Static instructions are useful when the agent's role and behavior remain consistent.

---

# Dynamic Context

Many applications need to provide runtime information to an agent.

For example:

```python
document = "Large document content..."

result = agent.run(
    f"""
Summarize the following document:

{document}
"""
)
```

The instruction remains consistent while the document changes for each execution.

For larger applications, dynamic context can also come from tools, memory, knowledge, retrievers, or workflow state.

---

# Prompt Composition

Large instruction sets are easier to maintain when organized into logical sections.

For example:

```text
Role

Goals

Rules

Constraints

Output Format

Examples
```

A structured prompt is easier to review than a single large paragraph.

Example:

```python
instructions = """
Role:
You are a senior Python engineer.

Goals:
Help developers solve practical programming problems.

Rules:
- Prefer simple solutions.
- Explain important tradeoffs.
- Use practical examples.

Output:
Provide concise explanations followed by code when appropriate.
"""
```

---

# Output Instructions

Prompts can explicitly describe the expected output format.

Markdown:

```text
Return your answer as Markdown.

Use headings and bullet points where appropriate.
```

JSON:

```text
Return valid JSON only.
```

Table:

```text
Return the result as a Markdown table.
```

For strongly typed application responses, prefer BindAI's structured-output support when an appropriate Python type is available.

For example:

```python
result = agent.run(
    "Generate a fictional person.",
    output=Person,
)
```

This lets the application work with a defined Python output type rather than relying only on textual formatting instructions.

---

# Reusing Instructions

Instructions can be reused through shared configuration.

For example, multiple agents can use the same instruction text:

```python
technical_writer_instructions = """
You are a technical writer.

Use clear and concise explanations.
"""

writer = (
    AgentBuilder()
    .name("writer")
    .model("openai:gpt-4.1-mini")
    .instructions(technical_writer_instructions)
    .build()
)

reviewer = (
    AgentBuilder()
    .name("reviewer")
    .model("openai:gpt-4.1-mini")
    .instructions(technical_writer_instructions)
    .build()
)
```

This keeps common behavior consistent across agents.

# Prompts and Conversation

Prompt instructions and conversation input serve different purposes.

A typical application conceptually combines:

```text
Agent Instructions
        +
Conversation Context
        +
Current User Input
        =
Model Execution
```

Instructions define how the agent should behave.

Conversation input provides the interaction context.

The exact execution pipeline depends on the configured agent capabilities and provider.

---

# Prompts and Memory

Memory is an agent capability that can provide persisted information to an execution.

For example:

```python
agent.use_memory(memory)
```

Prompts and memory therefore have different responsibilities:

* **Prompt** — defines agent behavior and instructions.
* **Memory** — provides stored information.
* **User input** — provides the current request.

Keep long-term application data in appropriate memory or knowledge systems rather than continuously expanding the system instructions.

---

# Prompts and Knowledge

Knowledge and retrieval provide external information that an agent can use during execution.

For example:

```python
agent.use_knowledge(knowledge)
```

A prompt should describe how the agent should use retrieved information.

For example:

```text
Use the provided documentation to answer questions.

If the required information is not available,
do not invent an answer.
```

The knowledge itself should remain in the knowledge system rather than being permanently embedded into the prompt.

---

# Prompts and Tools

Tools allow agents to obtain information or perform actions through registered functions.

For example:

```python
agent.tool(search)
```

The prompt can explain when a tool should be preferred.

```text
When current information is required,
use the available search tool instead of relying on memory.
```

This keeps behavioral guidance in the prompt while the actual capability remains implemented as a tool.

---

# Prompts in Workflows

When agents are used inside workflows, prompts can remain focused on the responsibility of the individual agent.

For example:

```text
Workflow
   │
   ├── Research Agent
   │
   ├── Analysis Agent
   │
   └── Review Agent
```

Each agent can have focused instructions rather than one large prompt attempting to control the entire workflow.

This makes multi-step AI applications easier to maintain.

---

# Prompt Organization

As a project grows, organize prompts by responsibility or domain.

Example:

```text
prompts/
├── support/
│   ├── assistant.md
│   └── escalation.md
│
├── sales/
│   ├── qualification.md
│   └── follow-up.md
│
├── documents/
│   ├── summarize.md
│   └── review.md
│
└── shared/
    ├── style.md
    └── safety.md
```

The exact directory structure is up to the application.

The important principle is to keep reusable prompt definitions discoverable and separate from unrelated business logic.

---

# Best Practices

* Keep instructions focused on the agent's responsibility.
* Separate behavioral instructions from runtime data.
* Reuse common instructions where appropriate.
* Clearly define expected output formats.
* Keep large documents out of system instructions.
* Use tools for actions and external operations.
* Use memory for persisted information.
* Use knowledge and retrieval for external information.
* Use structured output when the application requires a defined Python result.
* Review and update prompts as the application evolves.

A well-organized prompt strategy keeps agent behavior predictable while allowing the rest of the BindAI architecture—tools, memory, knowledge, and workflows—to handle their respective responsibilities.
