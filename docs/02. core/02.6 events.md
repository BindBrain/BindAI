# Events

BindAI provides a lightweight event mechanism for observing and extending agent execution.

Agents can register callbacks for named events using `Agent.on()` and emit custom events using `Agent.emit()`.

Events are useful for:

* Logging
* Monitoring
* Analytics
* Notifications
* Debugging
* Custom integrations
* Application-specific execution hooks

---

# Event API

The main event methods are available directly on `Agent`.

```python
agent.on(event, callback)
```

Register a callback for a named event.

```python
agent.emit(event, *args)
```

Emit a named event with optional arguments.

Both methods return or operate directly on the agent, making them easy to use as part of an agent configuration.

---

# Subscribing to an Event

Use `Agent.on()` to register a callback.

```python
def logger(*args):
    print("Event received:", args)


agent.on("message", logger)
```

The first argument is the event name.

The second argument is the callback that should run when the event is emitted.

The callback can accept the arguments associated with the event.

---

# Emitting an Event

Use `Agent.emit()` to publish a named event.

```python
agent.emit("message", "Hello from BindAI")
```

A callback registered for that event receives the emitted arguments.

For example:

```python
def logger(message):
    print(message)


agent.on("message", logger)

agent.emit("message", "Hello from BindAI")
```

Output:

```text
Hello from BindAI
```

---

# Custom Events

Event names are strings, so applications can define their own event names.

```python
def on_complete(result):
    print("Completed:", result)


agent.on("task_completed", on_complete)

agent.emit("task_completed", "Task finished")
```

This makes the event mechanism flexible enough for application-specific integrations.

---

# Event Arguments

`Agent.emit()` accepts any number of positional arguments after the event name.

```python
agent.emit(
    "task_completed",
    "report-123",
    True,
)
```

A callback can receive those values:

```python
def on_task_completed(task_id, success):
    print(task_id, success)


agent.on("task_completed", on_task_completed)
```

Output:

```text
report-123 True
```

The event name and callback contract should be kept consistent within an application.

---

# Using Events for Logging

Events can be used to centralize application logging.

```python
def log_event(*args):
    print("Agent event:", args)


agent.on("agent_event", log_event)
```

Application code can then emit events at important points:

```python
agent.emit(
    "agent_event",
    "execution started",
)
```

This keeps logging behavior separate from the core application logic.

---

# Events and Agent Execution

BindAI also exposes lifecycle hooks around agent execution.

The `Agent` API includes:

```python
agent.before_run(context)
agent.after_run(context, result)
agent.on_error(context, error)
```

These methods are different from named events.

Events provide a general callback mechanism.

Lifecycle methods receive execution-specific context and results.

---

# Before Execution

`before_run()` is called with the execution context.

```python
def before_run(context):
    print("Execution started")


agent.before_run = before_run
```

The context contains information associated with the current execution.

This hook is useful when application logic needs to inspect or prepare execution state before the agent runs.

---

# After Execution

`after_run()` receives both the execution context and the resulting `AgentResult`.

```python
def after_run(context, result):
    print("Execution completed")
    print(result.output)


agent.after_run = after_run
```

This is useful for:

* Logging results
* Recording metrics
* Auditing executions
* Triggering application actions

---

# Handling Execution Errors

Agents also expose `on_error()`.

It receives the execution context and the exception.

```python
def on_error(context, error):
    print("Agent execution failed:", error)


agent.on_error = on_error
```

This provides a centralized place for application-specific error handling or logging.

---

# Hooks

The `hook()` method provides another way to register custom execution logic.

```python
def custom_hook(context):
    print("Hook executed")


agent.hook(custom_hook)
```

Hooks are useful when reusable execution behavior should be attached to an agent.

The exact behavior of a hook depends on how the callback is used by the agent execution pipeline.

---

# Events vs Lifecycle Hooks

BindAI provides several mechanisms for extending agent behavior.

| Mechanism      | Purpose                                 |
| -------------- | --------------------------------------- |
| `on()`         | Register a callback for a named event   |
| `emit()`       | Emit a named event                      |
| `before_run()` | Handle logic before execution           |
| `after_run()`  | Handle logic after successful execution |
| `on_error()`   | Handle execution errors                 |
| `hook()`       | Register custom agent hook logic        |

A simple rule is:

* Use **events** when you want named application-level notifications.
* Use **`before_run()`** when logic belongs before execution.
* Use **`after_run()`** when logic belongs after execution.
* Use **`on_error()`** when execution failures need application-specific handling.
* Use **`hook()`** when reusable hook behavior should be attached to an agent.

---

# Multiple Event Subscribers

Multiple callbacks can be registered for the same event.

```python
def audit(*args):
    print("Audit:", args)


def metrics(*args):
    print("Metrics:", args)


agent.on("execution", audit)
agent.on("execution", metrics)
```

When the event is emitted:

```python
agent.emit("execution", "completed")
```

both callbacks can respond to the event.

This makes named events useful for decoupling application integrations.

---

# Events in a Larger Application

Events can connect an agent to other application components.

```text
Agent
  │
  ├── Event: execution_started
  │       ├── Logger
  │       └── Metrics
  │
  ├── Event: task_completed
  │       ├── Audit system
  │       └── Notification system
  │
  └── Event: execution_failed
          └── Error monitoring
```

The agent does not need to know how each subscriber processes the event.

---

# Keeping Event Handlers Lightweight

Event callbacks should generally perform small, fast operations.

Good event handlers include:

* Logging
* Updating counters
* Recording metrics
* Scheduling background work
* Triggering lightweight notifications

Avoid putting large amounts of business logic directly inside event callbacks.

For complex processing, emit an event and delegate the work to another application component.

---

# Best Practices

* Use descriptive event names.
* Keep event names consistent across the application.
* Keep callbacks small and focused.
* Document the arguments emitted with custom events.
* Use lifecycle methods for execution-specific behavior.
* Use `on_error()` for centralized execution error handling.
* Avoid putting heavy business logic directly inside event callbacks.
* Keep event-driven integrations separate from the core agent logic.

---

# Summary

BindAI's event system is based on named events registered directly on an `Agent`.

The core API is:

```text
agent.on(event, callback)
agent.emit(event, *args)
```

For execution lifecycle behavior, agents also provide:

```text
agent.before_run(context)
agent.after_run(context, result)
agent.on_error(context, error)
agent.hook(callback)
```

Together, these mechanisms allow applications to observe agent activity, attach execution behavior, and integrate agents with logging, monitoring, analytics, and other application services.
