# Providers

Providers connect BindAI to large language models.

Instead of interacting directly with an AI provider's SDK, BindAI communicates through a provider abstraction. This allows the same agent to run on different LLM providers with minimal code changes.

Supported providers include hosted APIs, self-hosted models, and local inference servers.

---

# Provider Architecture

Every agent communicates with a provider.

```text
Application

↓

Agent

↓

Provider

↓

Language Model
```

The provider is responsible for:

- sending requests
- receiving responses
- streaming tokens
- tool calling
- structured output
- reporting usage

Because every provider implements the same interface, the rest of your application remains provider agnostic.

# Configuring a Provider

The recommended approach is to configure your provider in **bindai.toml**.

```toml
provider = "openai"

model = "gpt-5"

temperature = 0.7
```

Then create your agent.

```python
from bindai import Agent

agent = (
    Agent()
    .from_project()
    .build()
)
```

The provider and model are loaded automatically.

---

# Explicit Provider Configuration

Providers can also be configured directly.

OpenAI:

```python
from bindai import Agent

agent = (
    Agent()
    .model("openai:gpt-5")
    .build()
)
```

Ollama:

```python
agent = (
    Agent()
    .model("ollama:llama3")
    .build()
)
```

LM Studio:

```python
agent = (
    Agent()
    .model("lmstudio:qwen3")
    .build()
)
```

The model string always follows:

```text
provider:model
```

# Environment Variables

Most hosted providers use environment variables.

Example:

```text
OPENAI_API_KEY=your_api_key
OPENAI_ORGANIZATION=optional
OPENAI_BASE_URL=https://api.openai.com/v1
```

BindAI automatically loads these values when using:

```python
Agent().model("openai:gpt-5")
```

using `python-dotenv`.

# Streaming

Streaming returns tokens as they are generated.

```python
agent = (
    Agent()
    .from_project()
    .build()
)

for chunk in agent.stream(
    "Explain transformers."
):
    print(chunk.delta, end="")
```

Streaming improves perceived latency in chat applications.

---

# Tool Calling

Providers that support function calling automatically integrate with BindAI tools.

```python
agent = (
    Agent()
    .tool(weather_tool)
    .tool(search_tool)
    .build()
)
```

When the model requests a tool:

```text
Model

↓

Tool

↓

Tool Result

↓

Model

↓

Final Response
```

BindAI manages the execution loop automatically.

---

# Structured Output

Providers that support structured generation can return Python objects.

```python
from pydantic import BaseModel

class User(BaseModel):
    name: str
    age: int

result = agent.run(
    "Generate a fictional user.",
    output=User,
)

print(result.output)
```

Instead of text, `result.output` becomes a validated `User` instance.

# Local Models

BindAI works with local inference servers.

Example using Ollama:

```python
agent = (
    Agent()
    .model("ollama:llama3")
    .build()
)
```

Example using LM Studio:

```python
agent = (
    Agent()
    .model("lmstudio:qwen3")
    .build()
)
```

No code changes are required beyond selecting a different provider.

---

# Switching Providers

Changing providers usually requires changing only one line.

```python
.model("openai:gpt-5")
```

↓

```python
.model("ollama:llama3")
```

Everything else remains identical.

This portability is one of BindAI's core design goals.

---

# Custom Providers

Custom providers can be registered through the provider registry.

A custom provider must implement the BindAI provider interface, allowing organizations to integrate proprietary or self-hosted AI systems.

Once registered, custom providers behave exactly like built-in providers.

---

# Provider Selection

For most applications, the recommended approach is:

- Configure the provider in `bindai.toml`
- Load it with `.from_project()`
- Override it only when necessary

This keeps configuration separate from application logic and makes switching providers straightforward.

---

# Best Practices

- Store secrets in environment variables.
- Configure providers in `bindai.toml`.
- Use `.from_project()` whenever possible.
- Choose the smallest model capable of the task.
- Enable streaming for interactive applications.
- Monitor token usage in production.
- Avoid provider-specific SDKs inside your application code.
