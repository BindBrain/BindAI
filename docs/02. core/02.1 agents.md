# Agents

Agents are the core building block of BindAI.

An agent combines a language model with instructions, tools, memory, knowledge retrieval, and middleware to create reusable AI behavior.

Every AI application built with BindAI starts with one or more agents.

---

# What is an Agent?

An agent is responsible for:

* Receiving user input
* Building prompts
* Calling an AI model
* Executing tools when needed
* Retrieving relevant knowledge
* Loading and storing memory
* Returning a structured result

Instead of writing model-specific code throughout your application, you interact with a single reusable abstraction.

---

# Agent Architecture

```text id="2mxgfa"
                User
                  │
                  ▼
              Agent.run()
                  │
      ┌───────────┴───────────┐
      │                       │
 Instructions             Conversation
      │                       │
      └───────────┬───────────┘
                  ▼
        Memory & Knowledge
                  │
                  ▼
            Language Model
                  │
          Tool Execution
                  │
                  ▼
            AgentResult
```

The execution pipeline is managed automatically by BindAI.

# Creating an Agent

The simplest agent only requires instructions.

The model provider is automatically loaded from your project configuration (`bindai.toml`).

```python id="ewylu2"
from bindai import Agent

agent = Agent(
    instructions="You are a helpful assistant."
)
```

If you want to override the project configuration:

```python id="sjv7pr"
from bindai import Agent

agent = Agent(
    provider="openai",
    model="gpt-4.1-mini",
    instructions="You are a helpful assistant."
)
```

---

# Running an Agent

Use the `run()` method to execute the agent.

```python id="hps0fi"
result = agent.run(
    "Explain what BindAI is."
)

print(result.output)
```

Example output:

```text id="1c5czz"
BindAI is an open-source Python framework for building AI agents, workflows, tools, memory, and knowledge retrieval systems.
```

---

# AgentResult

Every execution returns an `AgentResult`.

```python id="bopajk"
result = agent.run(
    "Hello!"
)

print(result.success)
print(result.output)
print(result.error)
```

Example:

```text id="ht4qcn"
True

Hello! How can I help you today?

None
```

This consistent response object simplifies error handling across your application.

# Configuring Models

Agents can explicitly choose a provider and model.

```python id="cvm3kv"
agent = Agent(
    provider="anthropic",
    model="claude-sonnet-4",
    instructions="You are an expert software architect."
)
```

Supported providers include:

* OpenAI
* Anthropic
* Ollama
* Azure OpenAI
* Custom providers

Switching providers requires changing only the configuration—not your application logic.

# Instructions

Instructions define how an agent behaves.

```python id="dy35ub"
agent = Agent(
    instructions="""
You are an experienced Python mentor.

Explain concepts clearly.

Use practical examples.

Keep answers concise.
"""
)
```

Good instructions describe:

* Role
* Tone
* Constraints
* Output expectations

# Conversations

Agents automatically maintain conversation history.

```python id="v7kv8j"
agent.run("Hello!")

agent.run("Who are you?")
```

The second request automatically includes the previous interaction.

Conversation history is separate from long-term memory.

---

# Tools

Agents can execute Python functions during reasoning.

```python id="t7hwp8"
from bindai import tool

@tool
def add(a: int, b: int):

    return a + b

agent.tool(add)
```

Now the model can decide when to call the calculator instead of generating the answer itself.

Agents can register multiple tools.

---

# Memory

Memory allows an agent to remember information across sessions.

```python id="a7h1xm"
agent.use_memory(
    memory
)
```

Supported providers include:

* In-memory
* Redis
* PostgreSQL
* Custom providers

Memory is optional and can be added later without changing agent logic.

---

# Knowledge (RAG)

Knowledge retrieval provides external information before model generation.

```python id="3trwxz"
agent.use_knowledge(
    knowledge
)
```

Knowledge sources may include:

* PDFs
* Markdown
* HTML
* Text files
* Documentation
* Vector databases

BindAI retrieves relevant information automatically before generating a response.

---

# Middleware

Middleware runs before and after every agent execution.

```python id="zhoj8r"
agent.use(
    LoggingMiddleware()
)
```

Typical middleware handles:

* Logging
* Authentication
* Telemetry
* Metrics
* Request preprocessing
* Response postprocessing

---

# Hooks

Hooks allow custom code to observe execution.

```python id="rkn9pr"
def after_run(context):

    print(context.result.output)

agent.on(after_run)
```

Hooks are useful for:

* Auditing
* Analytics
* Notifications
* Debugging

---

# Events

Every agent exposes an event bus.

Events include:

* Execution started
* Model request
* Model response
* Tool execution
* Execution completed

This enables integrations with monitoring and observability platforms.

---

# Streaming Responses

Instead of waiting for the full response, stream tokens as they are generated.

```python id="oc3r8v"
for chunk in agent.stream(
    "Write a short story."
):
    print(chunk.delta, end="")
```

Streaming is ideal for:

* Chat interfaces
* Long-form responses
* Live user experiences

---

# Structured Output

Agents can return validated Python objects.

```python id="2jgw7s"
from pydantic import BaseModel

class Person(BaseModel):

    name: str

    age: int

result = agent.run(
    "Generate a fictional person.",
    output=Person,
)

print(result.output)
```

The returned value is an instance of `Person` rather than raw text.

# Agent Builder

For advanced configuration, use `AgentBuilder`.

```python id="x1b8os"
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .instructions(
        "You are a helpful assistant."
    )
    .temperature(0.7)
    .build()
)
```

The builder provides a fluent API for configuring:

* Providers
* Models
* Temperature
* Tools
* Memory
* Knowledge
* Middleware
* Hooks
* Events

---

# Loading from a Project

BindAI can automatically configure an agent from the current project.

```python id="6uvgtr"
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .from_project()
    .build()
)
```

This loads:

* `bindai.toml`
* Environment variables
* Registered tools
* Default model configuration

making project setup nearly automatic.

# Using Agents in Workflows

Agents integrate directly with the workflow engine.

```python id="5mq6nk"
workflow.agent(
    agent,
    input_variable="question",
    output_variable="answer",
)
```

Workflow variables become agent input, and the result is stored back into the workflow context.

---

# Best Practices

* Give each agent a single responsibility.
* Keep instructions focused and concise.
* Prefer reusable tools over complex prompts.
* Store long-term information in memory rather than conversation history.
* Keep knowledge collections domain-specific.
* Use workflows to coordinate multiple agents instead of creating one large agent.
* Configure shared defaults through `bindai.toml` whenever possible.
