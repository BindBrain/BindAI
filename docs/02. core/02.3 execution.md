# Execution

Execution is the process BindAI uses to run an agent against an input and produce a result.

An execution can involve the configured model, instructions, tools, memory, knowledge, retrieval, middleware, and event handling depending on how the agent is configured.

The main execution interface is the agent's `run()` method.

---

# Running an Agent

A basic execution starts with `agent.run()`:

```python
result = agent.run("Explain what BindAI is.")
```

The method accepts:

```python
agent.run(
    message: str,
    output: type | None = None,
)
```

The first argument is the user message.

The optional `output` argument specifies a Python type for structured output.

---

# Execution Result

`agent.run()` returns an `AgentResult`.

```python
result = agent.run("Hello!")

print(result.success)
print(result.output)
print(result.error)
```

The result provides a consistent interface for checking whether execution succeeded and accessing the generated output or error.

A typical application can therefore use:

```python
if result.success:
    print(result.output)
else:
    print(result.error)
```

---

# Structured Output

Execution can return structured Python objects instead of plain text.

For example:

```python
from pydantic import BaseModel


class User(BaseModel):
    name: str
    age: int
```

Pass the type to `run()`:

```python
result = agent.run(
    "Generate a fictional user.",
    output=User,
)

print(result.output)
```

The application can then work with the structured result rather than parsing raw text manually.

# Tool Execution

Agents can be configured with tools.

```python
from bindai import AgentBuilder


agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .tools(search, calculator)
    .build()
)
```

Tools become part of the agent's execution capabilities.

A model may request a registered tool during execution. BindAI then coordinates the tool execution and subsequent agent processing.

Conceptually:

```text
User Input
    │
    ▼
 Agent
    │
    ▼
 Model
    │
    ├──► Tool
    │      │
    │      ▼
    │   Tool Result
    │      │
    └──────┘
    │
    ▼
Final Result
```

The number and order of tool interactions depend on the request and the configured agent.

---

# Tool Iterations

`AgentBuilder` provides a `max_tool_iterations()` configuration method.

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .max_tool_iterations(5)
    .build()
)
```

This allows applications to limit how many tool iterations an agent may perform during execution.

Use a reasonable limit for agents that have access to multiple tools or tools that may trigger additional model processing.

---

# Memory

Memory can be attached to an agent:

```python
agent.use_memory(memory)
```

Or configured through `AgentBuilder`:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .memory(memory)
    .build()
)
```

Memory is an optional execution capability.

It can provide stored information to an agent when the configured memory implementation supports it.

---

# Knowledge

Knowledge can also be attached to an agent:

```python
agent.use_knowledge(knowledge)
```

Or configured through the builder:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .knowledge(knowledge)

```

Knowledge systems allow applications to provide external information to agent execution.

The exact retrieval behavior depends on the configured knowledge implementation.

# Retrievers

Agents can use a retriever directly:

```python
agent.use_retriever(retriever)
```

The builder provides the corresponding configuration:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .retriever(retriever)
    .build()
)
```

Retrievers are useful when an application needs to locate relevant information before or during an agent task.

---

# Middleware

Middleware provides reusable execution behavior.

Attach middleware directly:

```python
agent.use_middleware(middleware)
```

Or configure it with the builder:

```python
agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")

```

* Logging
* Authentication
* Telemetry

# Execution Context

Some BindAI APIs operate with an `ExecutionContext`.

For example, the current `Agent.stream()` API accepts an execution context:

```python
agent.stream(context)
```

The execution context provides runtime information required by the relevant execution operation.

Context-aware APIs are particularly useful when integrating agents with larger application or workflow runtimes.

---

# Streaming

BindAI exposes streaming APIs for execution.

The low-level `stream()` method accepts an `ExecutionContext`:

```python
for chunk in agent.stream(context):
    print(chunk)
```

For conversational applications, BindAI also provides `stream_chat()`:

```python
for chunk in agent.stream_chat(
    "Explain neural networks."
):
    print(chunk)
```

Streaming is useful when an application needs to process output progressively.

Common use cases include:

* Chat interfaces
* Interactive applications
* Long-running responses
* Real-time user interfaces

---

# Chat Execution

BindAI also provides a `chat()` method:

```python
result = agent.chat(
    "Explain what BindAI is."
)

print(result.output)
```

Like `run()`, `chat()` accepts an optional structured-output type:

```python
result = agent.chat(
    "Generate a fictional user.",
    output=User,
)
```

Use the execution interface that best matches the application's interaction model.

# Events

Agents expose an event system through the `events` and `on()` APIs.

For example:

```python
agent.on(...)
```

An application can use agent events to integrate execution with:

* Monitoring
* Logging
* Analytics
* Auditing
* Observability

The exact event types and callback signatures depend on the event integration being used.

---

# Hooks

Agents expose lifecycle hook APIs including:

```python
agent.before_run(...)
agent.after_run(...)
agent.on_error(...)
agent.hook(...)
```

Hooks can be used to add application-specific behavior around agent execution.

Typical uses include:

* Custom logging
* Notifications
* Auditing
* Metrics
* External integrations

Keep hooks focused on cross-cutting behavior rather than putting core business logic into lifecycle callbacks.

# Execution and Projects

Agents can be configured from a BindAI project.

```python
from bindai import AgentBuilder


agent = (
    AgentBuilder()
    .from_project()
    .build()
)
```

This allows project-level configuration to be reused when constructing an agent.

Project-based configuration is useful when several agents share common model or application settings.

---

# Execution and Workflows

Agents can also participate in larger workflows.

A workflow can coordinate agent execution with other operations such as:

* Conditions
* Loops
* Parallel execution
* Retries
* Timeouts
* Human tasks
* Scheduling

This allows individual agents to remain focused on specific responsibilities while workflows handle higher-level orchestration.

Conceptually:

```text
Workflow
    │
    ├── Agent
    │
    ├── Condition
    │
    ├── Agent
    │
    └── Final Result
```

---

# Error Handling

Always check the returned `AgentResult` when application behavior depends on successful execution.

```python
result = agent.run(
    "Perform the requested operation."
)

if not result.success:
    print("Execution failed:")
    print(result.error)
else:
    print(result.output)
```

This keeps application-level error handling independent from provider-specific response formats.

# A Complete Execution Example

The following example combines several verified agent capabilities:

```python
from bindai import AgentBuilder


agent = (
    AgentBuilder()
    .name("assistant")
    .model("openai:gpt-4.1-mini")
    .instructions("""
You are a helpful AI assistant.

Provide clear and concise answers.
""")
    .max_tool_iterations(5)
    .build()
)


result = agent.run(
    "Explain what BindAI is."
)


if result.success:
    print(result.output)
else:
    print(result.error)
```

The same agent can later be extended with additional capabilities:

```python
agent.tool(search)
agent.use_memory(memory)
agent.use_knowledge(knowledge)
agent.use_retriever(retriever)
agent.use_middleware(middleware)
```

This allows the execution layer to grow with the application while keeping the primary agent interface consistent.

---

# Execution Best Practices

* Use `run()` for general agent execution.
* Use `chat()` for conversational execution.
* Use structured output when downstream code requires predictable data.
* Configure tool iteration limits for tool-using agents.
* Use memory only when persisted information is required.
* Use knowledge and retrievers for external information.
* Use middleware for reusable cross-cutting behavior.
* Use hooks and events for lifecycle integrations.
* Check `AgentResult.success` when execution failure needs to be handled explicitly.
* Use workflows when multiple agents or execution stages need to be coordinated.

BindAI keeps the primary execution interface simple while allowing applications to add capabilities as their requirements grow.
