# Execution

Execution is the process BindAI follows to transform a user request into a final response.

Rather than sending a prompt directly to a language model, BindAI runs a structured execution pipeline that prepares context, retrieves knowledge, loads memory, executes tools when required, and returns a consistent result.

The entire lifecycle is managed automatically.

---

# The Execution Pipeline

Every agent follows the same high-level execution flow.

```text id="6n4kzf"
User Input
      │
      ▼
Initialize Request
      │
      ▼
Load Conversation
      │
      ▼
Load Memory (optional)
      │
      ▼
Retrieve Knowledge (optional)
      │
      ▼
Model Generation
      │
      ▼
Tool Calls (optional)
      │
      ▼
Model Generation
      │
      ▼
Store Memory
      │
      ▼
Return AgentResult
```

Depending on the agent configuration, some stages may be skipped.

---

# Step 1 — Initialize Request

Execution begins when you call:

```python id="3zgjtt"
result = agent.run("Explain what BindAI is.")
```

BindAI creates an execution context that contains:

* User input
* Agent configuration
* Conversation state
* Runtime variables
* Metadata

This context is shared throughout the execution pipeline.

---

# Step 2 — Load Conversation

If the agent has already been used, previous messages are automatically included.

```text id="plvg0s"
System Prompt

↓

Conversation History

↓

Current User Message
```

Conversation history gives the model short-term context.

---

# Step 3 — Load Memory

If memory is attached, BindAI retrieves relevant long-term information.

```python id="9gtfwl"
agent.use_memory(memory)
```

Memory may contain:

* User preferences
* Previous conversations
* Stored facts
* Application state

Without memory, every execution starts fresh.

---

# Step 4 — Retrieve Knowledge

If the agent has a knowledge source, BindAI performs retrieval before calling the model.

```python id="v1lfsv"
agent.use_knowledge(knowledge)
```

Typical sources include:

* Documentation
* PDFs
* Markdown
* HTML
* Vector databases

Retrieved documents are added to the prompt automatically.

---

# Step 5 — Build the Model Request

After combining:

* Instructions
* Conversation
* Memory
* Retrieved knowledge
* Current user input

BindAI constructs the final request sent to the configured provider.

```text id="18ywsn"
Instructions

+

Conversation

+

Memory

+

Knowledge

+

User Input

=

Model Request
```

---

# Step 6 — Generate a Response

The configured model generates an initial response.

```python id="hncx5u"
provider.generate(request)
```

The model may return:

* Plain text
* Structured output
* Tool calls
* Streaming tokens

---

# Step 7 — Tool Execution

If the model requests one or more tools, BindAI executes them automatically.

Example:

```text id="jlwmwc"
User

↓

Model

↓

Weather Tool

↓

Weather Result

↓

Model

↓

Final Response
```

Tool results become part of the conversation before another model call.

This entire process is automatic.

---

# Multiple Tool Calls

One execution can involve several tool calls.

```text id="dtjmzk"
Model

↓

Calculator

↓

Model

↓

Database

↓

Model

↓

Email Tool

↓

Model

↓

Final Answer
```

Agents continue until no additional tool calls are requested.

---

# Tool Iteration Limits

To prevent infinite loops, BindAI limits tool execution.

The limit is configurable.

```python id="2txjjr"
agent = Agent(max_tool_iterations=5)
```

If the limit is reached, execution stops safely.

---

# Step 8 — Store Memory

After the response is complete, memory providers may persist new information.

This allows future executions to remember previous interactions.

Conversation history and memory remain separate concepts.

---

# Step 9 — Return AgentResult

Every execution returns an `AgentResult`.

```python id="9wsmle"
result = agent.run("Hello!")

print(result.success)
print(result.output)
print(result.error)
```

Typical output:

```text id="rbd3mf"
True

Hello! How can I help you today?

None
```

---

# AgentResult

The returned object contains consistent execution information.

| Property  | Description                                        |
| --------- | -------------------------------------------------- |
| `success` | Indicates whether execution completed successfully |
| `output`  | Final response                                     |
| `error`   | Exception or failure message (if any)              |

Applications rarely need provider-specific error handling because every provider returns the same result structure.

---

# Structured Output

Agents can return validated Python objects.

```python id="0s6nk8"
from pydantic import BaseModel


class User(BaseModel):
    name: str

    age: int


result = agent.run(
    "Generate a fictional user.",
    output=User,
)

print(result.output)
```

Instead of raw text, `result.output` becomes a `User` instance.

---

# Streaming Execution

Streaming begins immediately after generation starts.

```python id="gcq8j5"
for chunk in agent.stream("Write a poem."):
    print(chunk.delta, end="")
```

Streaming is recommended for:

* Chat applications
* Long responses
* Interactive user interfaces

---

# Execution Context

Every execution has an internal context object.

It stores:

* Variables
* Metadata
* Runtime state
* Conversation
* Events

Tools, workflows, and middleware can access this context during execution.

---

# Middleware

Middleware executes before and after the pipeline.

```python id="1lzjnv"
agent.use(LoggingMiddleware())
```

Typical middleware handles:

* Authentication
* Logging
* Monitoring
* Metrics
* Rate limiting
* Request preprocessing
* Response postprocessing

Middleware is ideal for application-wide behavior.

---

# Events

BindAI publishes lifecycle events throughout execution.

Typical events include:

```text id="0j6vtx"
Execution Started

↓

Model Request

↓

Model Response

↓

Tool Executed

↓

Execution Finished
```

Applications can subscribe to events for:

* Analytics
* Monitoring
* Auditing
* Observability

---

# Hooks

Hooks execute custom Python logic during the lifecycle.

```python id="xnd4hf"
def after_run(context):

    print(context.result.output)


agent.on(after_run)
```

Hooks are useful for:

* Notifications
* Custom logging
* Integrations
* Application-specific behavior

---

# Error Handling

If execution fails, BindAI still returns an `AgentResult`.

```python id="sog7v4"
AgentResult(success=False, output=None, error="Authentication failed.")
```

This makes error handling consistent regardless of the underlying provider.

# Complete Execution Example

```text id="d2lmow"
User Request

↓

Initialize

↓

Conversation

↓

Memory

↓

Knowledge

↓

Language Model

↓

Tool Execution

↓

Language Model

↓

Memory Update

↓

```

Simple requests may complete after one model call.

More advanced requests may involve multiple rounds of tool execution before producing the final answer.

---

# Best Practices

* Keep prompts focused on one responsibility.
* Use memory only when persistence is required.
* Keep knowledge collections domain-specific.
* Register small reusable tools instead of large complex ones.
* Enable streaming for interactive applications.
* Use middleware for cross-cutting concerns.
* Subscribe to events for monitoring rather than modifying execution logic.
* Return structured output whenever downstream code depends on predictable data.
