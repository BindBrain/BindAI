# Tool Results

Every BindAI tool execution returns a **`ToolResult`**.

`ToolResult` is the standard result object produced by the `Tool` abstraction. It records whether the tool executed successfully, the returned value, and any error that occurred.

This keeps tool execution predictable for agents and other parts of the framework.

---

# ToolResult

`ToolResult` is a dataclass with three fields:

```python
ToolResult(
    success: bool,
    value: Any = None,
    error: str | None = None,
)
```

The fields are:

| Field     | Description                                          |
| --------- | ---------------------------------------------------- |
| `success` | Whether the tool executed successfully               |
| `value`   | The value returned by the underlying Python function |
| `error`   | Error message when execution fails                   |

`ToolResult` uses `slots=True`.

---

# How Tool Results Are Created

Tools automatically convert function execution into a `ToolResult`.

For example:

```python
from bindai import tool


@tool
def multiply(a: int, b: int) -> int:
    return a * b
```

When the tool is executed:

```python
result = multiply(4, 5)

print(result)
```

The result is equivalent to:

```python
ToolResult(
    success=True,
    value=20,
    error=None,
)
```

The Python function only needs to return its normal Python value.

You do **not** need to construct a `ToolResult` manually.

---

# Successful Execution

When the underlying function completes successfully, `Tool` wraps its return value in a successful result.

Conceptually, BindAI performs:

```python
value = function(*args, **kwargs)

return ToolResult(
    success=True,
    value=value,
)
```

For example:

```python
@tool
def square(value: int) -> int:
    return value * value
```

Calling:

```python
result = square(7)
```

produces:

```python
ToolResult(
    success=True,
    value=49,
    error=None,
)
```

---

# Failed Execution

If the underlying function raises an exception, BindAI catches it and returns a failed `ToolResult`.

The implementation effectively performs:

```python
try:
    value = function(*args, **kwargs)

    return ToolResult(
        success=True,
        value=value,
    )

except Exception as e:
    return ToolResult(
        success=False,
        error=str(e),
    )
```

For example:

```python
@tool
def divide(a: int, b: int) -> float:
    return a / b
```

Calling:

```python
result = divide(10, 0)
```

produces a failed result similar to:

```python
ToolResult(
    success=False,
    value=None,
    error="division by zero",
)
```

The exact error string depends on the exception raised by the underlying function.

---

# Checking Success

Applications can inspect the `success` field.

```python
result = multiply(4, 5)

if result.success:
    print(result.value)
else:
    print(result.error)
```

This provides a simple way to handle tool execution failures.

---

# Accessing the Returned Value

The successful function return value is stored in `value`.

```python
@tool
def greet(name: str) -> str:
    return f"Hello, {name}!"


result = greet("Alice")

print(result.value)
```

Output:

```text
Hello, Alice!
```

The field is named **`value`**, not `output`.

---

# Returning Different Python Values

A tool can return normal Python values.

## Strings

```python
@tool
def ping() -> str:
    return "Pong"
```

The result contains:

```python
ToolResult(
    success=True,
    value="Pong",
)
```

## Numbers

```python
@tool
def square(value: int) -> int:
    return value * value
```

The result contains:

```python
ToolResult(
    success=True,
    value=25,
)
```

## Lists

```python
@tool
def colors() -> list[str]:
    return [
        "red",
        "green",
        "blue",
    ]
```

The list is stored in `result.value`.

## Dictionaries

```python
@tool
def profile() -> dict:
    return {
        "name": "Alice",
        "age": 28,
    }
```

The dictionary is stored in `result.value`.

The `ToolResult.value` field is typed as `Any`, so the underlying tool can return different Python value types.

---

# Tool Exceptions

Tool exceptions are handled by the `Tool` object.

An exception raised by the underlying function does not escape from `Tool.__call__()`.

Instead, the exception is converted into:

```python
ToolResult(
    success=False,
    error=str(exception),
)
```

This gives callers a consistent result object for both successful and failed executions.

---

# ToolExecutor

BindAI also provides `ToolExecutor`.

```python
from bindai import ToolExecutor
```

`ToolExecutor` is initialized with a `ToolRegistry`:

```python
executor = ToolExecutor(registry)
```

Its execution method is:

```python
executor.execute(
    tool_name,
    *args,
    **kwargs,
)
```

The method returns a `ToolResult`.

---

# Unknown Tools

If `ToolExecutor` cannot find the requested tool in its registry, it returns a failed `ToolResult`.

The implementation uses:

```python
ToolResult(
    success=False,
    error=f"Unknown tool '{tool_name}'",
)
```

For example:

```python
result = executor.execute("missing_tool")
```

produces a result similar to:

```python
ToolResult(
    success=False,
    value=None,
    error="Unknown tool 'missing_tool'",
)
```

This avoids an unhandled exception for an unknown registered tool name.

---

# Tool Execution Flow

The current tool execution flow can be summarized as:

```text
Python Function
      │
      ▼
    Tool
      │
      ├── Function succeeds
      │       │
      │       ▼
      │   ToolResult(
      │       success=True,
      │       value=...
      │   )
      │
      └── Function raises exception
              │
              ▼
          ToolResult(
              success=False,
              error=...
          )
```

When using `ToolExecutor`:

```text
Tool Name
   │
   ▼
ToolRegistry
   │
   ├── Tool found
   │      │
   │      ▼
   │   Tool.__call__()
   │      │
   │      ▼
   │   ToolResult
   │
   └── Tool not found
          │
          ▼
      Failed ToolResult
```

---

# ToolResult vs AgentResult

`ToolResult` is specifically for tool execution.

`AgentResult` is the result returned from an agent execution.

They have different fields and responsibilities.

For tools:

```python
ToolResult(
    success=True,
    value=...,
    error=None,
)
```

For agents, the result API is separate.

Do not assume that the field names of one result type are identical to another.

---

# Current API

The currently verified `ToolResult` API is:

```python
ToolResult(
    success: bool,
    value: Any = None,
    error: str | None = None,
)
```

The available attributes are:

```python
result.success
result.value
result.error
```

There are currently no verified `ToolResult.success()` or `ToolResult.failure()` helper methods.

---

# Best Practices

* Return normal Python values from tool functions.
* Let `Tool` wrap those values into `ToolResult`.
* Check `result.success` before using `result.value`.
* Inspect `result.error` when execution fails.
* Use descriptive exceptions for expected failures.
* Do not rely on an `output` field for `ToolResult`; use `value`.
* Keep tool functions focused on a single responsibility.
* Treat `ToolResult` as the boundary between tool execution and the caller.

---

# Summary

`ToolResult` is BindAI's standard result object for tool execution.

The `Tool` abstraction automatically wraps successful Python return values in a `ToolResult` and converts raised exceptions into failed `ToolResult` objects.

The current result structure is:

```text
ToolResult
├── success
├── value
└── error
```

This provides a simple and consistent contract for executing tools and handling failures.
