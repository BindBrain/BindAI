# Tool Results

Every tool execution in BindAI returns a **ToolResult**.

A `ToolResult` provides a consistent interface between tools, agents, and workflows, allowing the execution engine to handle successful outputs, structured data, and failures in a predictable way.

Instead of passing raw Python return values through the execution pipeline, BindAI wraps every execution result in a standard object.

---

# Why Tool Results?

A standardized result object makes tool execution reliable.

Benefits include:

- consistent execution behavior
- predictable error handling
- workflow compatibility
- structured outputs
- easier debugging
- provider-independent execution

Every tool behaves the same way regardless of what it actually does.

---

# Successful Execution

A successful tool returns a `ToolResult`.

```python
from bindai_tools import tool
from bindai_tools import ToolResult


@tool
def multiply(a: int, b: int) -> ToolResult:
    return ToolResult.success(a * b)
```

When the tool executes successfully, the output becomes available to the agent or workflow.

---

# Failed Execution

If a tool cannot complete its task, it should return a failed result.

```python
from bindai_tools import tool
from bindai_tools import ToolResult


@tool
def load_customer(customer_id: int) -> ToolResult:
    return ToolResult.failure("Customer not found.")
```

The execution engine captures the failure without crashing the application.

---

# ToolResult Structure

A ToolResult contains three primary fields.

| Field | Description |
|--------|-------------|
| `success` | Indicates whether execution succeeded |
| `output` | Returned value from the tool |
| `error` | Error message when execution fails |

Example:

```python
ToolResult(
    success=True,
    output={"id": 42},
    error=None,
)
```

---

# Returning Primitive Values

Tools commonly return simple values.

```python
@tool
def square(value: int) -> ToolResult:
    return ToolResult.success(value * value)
```

---

# Returning Collections

Lists and dictionaries work naturally.

```python
@tool
def colors() -> ToolResult:
    return ToolResult.success(
        [
            "red",
            "green",
            "blue",
        ]
    )
```

---

# Returning Structured Objects

Tools can also return Pydantic models or other structured objects.

```python
from pydantic import BaseModel


class Customer(BaseModel):
    id: int
    name: str


@tool
def customer() -> ToolResult:
    return ToolResult.success(
        Customer(
            id=1,
            name="Alice",
        )
    )
```

Structured outputs make downstream processing significantly easier.

---

# Using Tool Results in Agents

Agents automatically receive tool results during reasoning.

```text
User

↓

Language Model

↓

Tool Request

↓

Tool Execution

↓

ToolResult

↓

Language Model

↓

Final Response
```

The language model reasons over the returned data before generating its final answer.

---

# Using Tool Results in Workflows

Workflow nodes can consume tool outputs directly.

```text
Load Customer

↓

Customer

↓

Load Orders

↓

Invoice

↓

Generate Report
```

Each node receives the output produced by the previous tool.

---

# Error Recovery

Because every tool returns a standard result object, workflows can recover gracefully.

Possible recovery strategies include:

- retrying the tool
- executing an alternative tool
- branching to an error path
- requesting human approval
- stopping execution

This integrates naturally with BindAI's workflow engine.

---

# Logging

Tool results are ideal for monitoring.

Typical information includes:

- execution duration
- success or failure
- returned output
- error details

Applications can subscribe to events or use middleware to record tool activity.

---

# Best Practices

- Return `ToolResult` from every tool.
- Return structured data whenever possible.
- Keep outputs reasonably small.
- Use clear error messages.
- Handle expected failures gracefully.
- Avoid exposing provider-specific exceptions.
- Keep tools deterministic whenever possible.

---

# Summary

`ToolResult` provides a consistent contract between tools, agents, and workflows.

Whether a tool succeeds or fails, the execution engine always receives a predictable object, making applications easier to compose, debug, and extend.
