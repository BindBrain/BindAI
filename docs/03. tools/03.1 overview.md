# Tools Overview

Tools give BindAI agents the ability to interact with the outside world.

Instead of relying only on a language model, an agent can execute Python functions, call APIs, query databases, search documents, perform calculations, or integrate with business systems.

Tools are one of the core building blocks of agentic applications.

---

# What is a Tool?

A tool is a Python function that an AI model can invoke during an agent execution.

Typical examples include:

- Searching the web
- Calling REST APIs
- Reading files
- Sending emails
- Querying databases
- Performing calculations
- Retrieving business information
- Executing custom application logic

The language model decides **when** a tool should be used.

BindAI validates the request, executes the tool, and returns the result back to the model so it can continue reasoning.

---

# How Tool Calling Works

```text
User

↓

Agent

↓

Language Model

↓

Tool Selection

↓

Tool Execution

↓

Tool Result

↓

Language Model

↓

Final Response
```

Once tools are registered with an agent, this entire process happens automatically.

---

# Why Use Tools?

Language models cannot:

- Access live information
- Read your database
- Call internal APIs
- Perform secure business operations
- Execute Python code directly

Tools solve these limitations.

They allow agents to:

- Access real-time information
- Perform deterministic operations
- Automate business processes
- Integrate with existing systems
- Retrieve external knowledge
- Execute reusable application logic

---

# Creating a Tool

The easiest way to create a tool is by decorating a Python function.

```python
from bindai import tool


@tool
def get_weather(city: str) -> str:
    return f"The weather in {city} is sunny."
```

The decorator automatically converts the function into a BindAI tool.

---

# Registering Tools

Register tools when building an agent.

```python
from bindai import AgentBuilder

agent = (
    AgentBuilder()
    .model("openai:gpt-5")
    .tool(get_weather)
    .build()
)
```

Multiple tools can be registered.

```python
agent = (
    AgentBuilder()
    .tool(search)
    .tool(get_weather)
    .tool(calculate)
    .build()
)
```

---

# Tool Discovery

Before sending a request to the language model, BindAI automatically converts every registered tool into a provider-compatible schema.

The model receives information such as:

- Tool name
- Description
- Parameters
- Parameter types
- Return description

The model then decides which tool should be called.

---

# Automatic Tool Calling

Example conversation

```text
User

↓

"What is the weather in Tokyo?"

↓

Model selects get_weather()

↓

BindAI executes tool

↓

Tool returns result

↓

Model writes final response
```

You never call the tool manually.

---

# Parameters

Parameters are automatically extracted from the Python function.

```python
@tool
def search(
    query: str,
    limit: int = 5,
):
    ...
```

The model may generate

```text
search(
    query="BindAI",
    limit=5
)
```

BindAI validates the arguments before executing the function.

---

# Type Validation

Tool arguments are validated automatically.

```python
@tool
def multiply(
    a: int,
    b: int,
):
    return a * b
```

If invalid arguments are produced by the model, BindAI reports the validation failure instead of executing the function.

This improves reliability and safety.

---

# Tool Results

Every tool returns a structured result internally.

Typical successful execution

```python
ToolResult(
    success=True,
    output="..."
)
```

The output becomes part of the conversation and is available to the language model during the next reasoning step.

---

# Multiple Tool Calls

A single agent execution may involve multiple tools.

```text
Search

↓

Database

↓

Calculator

↓

Language Model

↓

Final Answer
```

BindAI automatically manages the tool execution loop until the model produces a final response.

The maximum number of iterations can be configured.

# Shared Tools

Projects often reuse tools across multiple agents.

```python
weather = get_weather

support_agent.tool(weather)

sales_agent.tool(weather)

research_agent.tool(weather)
```

This avoids duplicated implementations and keeps behavior consistent.

---

# Tool Context

Tools can access execution context when required.

The context may include:

- Workflow variables
- Metadata
- Runtime information
- User information
- Execution state

This allows tools to participate in complex workflows without relying only on function parameters.

---

# Error Handling

If a tool fails, BindAI captures the error.

Example

```python
ToolResult(
    success=False,
    error="Database unavailable."
)
```

The language model can often recover by:

- Calling another tool
- Asking the user for clarification
- Explaining the failure gracefully

---

# Tool Lifecycle

```text
Register Tool

↓

Expose Schema

↓

Model Chooses Tool

↓

Validate Parameters

↓

Execute Function

↓

Return Result

↓

Continue Reasoning
```

This lifecycle is identical regardless of which LLM provider is being used.

---

# Best Practices

- Design each tool to perform one clear task.
- Write concise descriptions.
- Use descriptive parameter names.
- Add Python type hints.
- Keep outputs deterministic whenever possible.
- Handle failures gracefully.
- Avoid long-running blocking operations.
- Reuse shared tools across multiple agents.
- Prefer several small tools over one large tool.

---

# Summary

Tools extend language models with real-world capabilities.

They allow agents to interact with external systems, automate workflows, retrieve live information, and execute business logic while keeping the execution process consistent, safe, and provider-independent.
