# Tools Overview

Tools give BindAI agents the ability to interact with application code and external systems.

A tool is a callable operation that an agent can invoke when additional functionality is required.

Tools can be used for:

* Calling APIs
* Querying databases
* Searching documents
* Performing calculations
* Reading or writing application data
* Executing business logic
* Integrating with external services

Tools extend an agent beyond what a language model can do on its own.

---

# What is a Tool?

A BindAI tool represents an operation that an agent can execute.

The simplest tool can be a Python function:

```python
def get_weather(city: str) -> str:
    return f"The weather in {city} is sunny."
```

Tools can then be attached to an agent.

```python
agent.tool(get_weather)
```

BindAI exposes both `tool()` and `add_tool()` on `Agent` for registering tools.

---

# Creating a Tool

BindAI provides a `tool` decorator for defining tools.

```python
from bindai import tool


@tool
def get_weather(city: str) -> str:
    return f"The weather in {city} is sunny."
```

The decorator allows BindAI to treat the function as a tool that can be registered with an agent.

Python type hints should be used whenever possible.

They make the tool interface clearer and allow BindAI and the underlying provider to understand the expected parameters.

---

# Registering a Tool

A tool can be registered directly on an agent.

```python
from bindai import Agent


agent = Agent(
    provider="openai",
    model="gpt-5",
    instructions="You are a helpful assistant.",
)

agent.tool(get_weather)
```

`add_tool()` provides an equivalent registration method:

```python
agent.add_tool(get_weather)
```

Both methods attach a tool to the agent.

---

# Registering Tools with AgentBuilder

Tools can also be configured through `AgentBuilder`.

```python
from bindai import AgentBuilder


agent = (
    AgentBuilder()
    .model("openai:gpt-5")
    .tools(get_weather)
    .build()
)
```

Multiple tools can be supplied to `tools()`:

```python
agent = (
    AgentBuilder()
    .model("openai:gpt-5")
    .tools(
        search,
        get_weather,
        calculate,
    )
    .build()
)
```

This is useful when an agent has several capabilities.

---

# How Tool Calling Works

At a high level, tool-enabled execution follows this process:

```text
User
  │
  ▼
Agent
  │
  ▼
Language Model
  │
  ▼
Tool Selection
  │
  ▼
Tool Execution
  │
  ▼
Tool Result
  │
  ▼
Language Model
  │
  ▼
Final Response
```

The model determines whether a registered tool is appropriate for the request.

When a tool call is requested, BindAI executes the corresponding tool and makes the result available to the ongoing execution.

---

# Why Use Tools?

A language model alone may not have access to application-specific capabilities.

Tools can provide access to:

* Live data
* Internal APIs
* Databases
* Deterministic calculations
* Application state
* Business operations
* External services

For example, instead of asking a model to guess a calculation:

```python
@tool
def multiply(a: int, b: int) -> int:
    return a * b
```

The agent can use the deterministic Python operation when appropriate.

---

# Tool Parameters

Tool parameters are defined by the Python function signature.

```python
@tool
def search(
    query: str,
    limit: int = 5,
):
    ...
```

The tool exposes two parameters:

* `query` — a string search query
* `limit` — the maximum number of results

Type hints communicate the expected parameter types.

Default values can be used when a parameter is optional.

---

# Type Hints

Type hints make tools easier to understand and integrate.

```python
@tool
def multiply(
    a: int,
    b: int,
) -> int:
    return a * b
```

The signature communicates:

```text
a → integer
b → integer
return value → integer
```

Use clear type annotations for tool parameters whenever possible.

---

# Tool Descriptions

Tool descriptions should clearly explain what an operation does.

For example:

```python
@tool
def get_weather(city: str) -> str:
    """Return the current weather for a city."""
    return f"The weather in {city} is sunny."
```

A clear description helps the model determine when the tool is appropriate.

Avoid descriptions that are vague or overly broad.

---

# Multiple Tools

An agent can have multiple tools.

```python
agent = (
    AgentBuilder()
    .model("openai:gpt-5")
    .tools(
        search,
        get_weather,
        calculate,
    )
    .build()
)
```

The model can choose among the registered capabilities based on the user's request.

For example:

```text
User
  │
  ├── Search request ──► search()
  │
  ├── Weather request ─► get_weather()
  │
  └── Calculation ─────► calculate()
```

---

# Tool Execution

When a model requests a tool, BindAI executes the registered callable.

Conceptually:

```text
Model
  │
  ▼
Tool Call
  │
  ▼
Python Function
  │
  ▼
Return Value
  │
  ▼
Model
```

The returned value can then be used by the model to continue generating the final response.

---

# Multiple Tool Calls

An agent execution may involve more than one tool call.

For example:

```text
User
  │
  ▼
Model
  │
  ▼
Search Tool
  │
  ▼
Model
  │
  ▼
Calculator Tool
  │
  ▼
Model
  │
  ▼
Final Response
```

This allows an agent to combine several capabilities during a single request.

The number of tool iterations can be configured through `AgentBuilder`.

```python
agent = (
    AgentBuilder()
    .model("openai:gpt-5")
    .max_tool_iterations(5)
    .tools(search, calculate)
    .build()
)
```

---

# Tool Results

Tool execution results are represented internally by BindAI's tool execution system.

The public package exposes `ToolResult` as part of the BindAI API.

```python
from bindai import ToolResult
```

A successful tool execution can contain an output value, while a failed execution can contain an error.

The exact result handling depends on the tool execution path being used.

---

# Reusing Tools

Tools can be reused across multiple agents.

```python
weather = get_weather

support_agent.tool(weather)
sales_agent.tool(weather)
research_agent.tool(weather)
```

This keeps shared functionality in one implementation instead of duplicating the same logic across agents.

---

# Tools and Project Configuration

Tools can also be configured as part of a BindAI project.

When using:

```python
agent = AgentBuilder().from_project().build()
```

the project configuration can provide the agent with its configured tools.

This allows application code to keep agent configuration separate from the execution code.

A typical project might organize tools like this:

```text
my-ai-app/

├── agents/
│   └── assistant.py
│
├── tools/
│   ├── search.py
│   ├── weather.py
│   └── calculator.py
│
└── bindai.toml
```

---

# Tool Context

Some tools may need access to information beyond their explicit function arguments.

For advanced integrations, tools can participate in the execution context used by the agent.

This can be useful for applications involving:

* Runtime metadata
* Workflow state
* Application state
* User-specific information
* External service configuration

The exact context interface depends on the tool and execution API being used.

---

# Error Handling

Tools can fail during execution.

For example:

```python
@tool
def get_data():
    raise RuntimeError("Database unavailable.")
```

Applications should design tools to handle expected failures appropriately.

A failed tool execution can then be handled by the agent execution pipeline rather than requiring every caller to implement provider-specific error handling.

For external systems, prefer explicit error messages that give the agent enough information to recover or explain the problem.

---

# Tool Lifecycle

A typical tool-enabled execution follows this lifecycle:

```text
Register Tool
      │
      ▼
Expose Tool
      │
      ▼
Model Selects Tool
      │
      ▼
Execute Tool
      │
      ▼
Return Tool Result
      │
      ▼
Continue Agent Execution
      │
      ▼
Final Response
```

The agent remains responsible for coordinating the interaction between the model and registered tools.

---

# Tool Categories

Tools can represent many kinds of application operations.

Common categories include:

* Search
* APIs
* Databases
* File operations
* Calculations
* Knowledge retrieval
* External services
* Business systems
* Internal application logic

BindAI does not require all tools to belong to a particular category.

A tool is simply a callable capability that an agent can use.

---

# Designing Good Tools

Good tools should have a clear and limited responsibility.

For example, prefer:

```python
@tool
def get_weather(city: str):
    ...
```

over a single tool that attempts to handle:

```text
weather
search
database access
email
file operations
payments
```

Small tools are easier for both developers and language models to understand.

---

# Best Practices

* Give each tool one clear responsibility.
* Use descriptive function and parameter names.
* Add Python type hints.
* Write concise tool descriptions.
* Validate external inputs.
* Keep tool outputs focused and useful.
* Handle expected failures gracefully.
* Avoid unnecessary side effects.
* Keep long-running operations outside latency-sensitive paths when possible.
* Reuse common tools across agents.
* Prefer several focused tools over one large tool.

---

# Summary

Tools extend BindAI agents with capabilities beyond language generation.

The core registration APIs are:

```python
agent.tool(my_tool)
```

and:

```python
agent.add_tool(my_tool)
```

For builder-based configuration:

```python
agent = (
    AgentBuilder()
    .tools(my_tool)
    .build()
)
```

Once registered, tools can participate in agent execution and allow models to interact with application logic, external services, and deterministic operations.

The result is an agent that can do more than generate text: it can **take actions and use application capabilities as part of its execution**.
