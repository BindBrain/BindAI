# Tool Context

Tool Context gives tools access to the current execution environment.

Instead of relying only on function parameters, a tool can access workflow variables, execution metadata, runtime state, and other information about the current request.

This allows tools to cooperate naturally with agents and workflows.

---

# What is Tool Context?

Every agent and workflow execution creates an execution context.

That context travels through the entire execution pipeline.

It may contain:

- Workflow variables
- Runtime metadata
- Execution state
- User information
- Previous tool outputs
- Agent information

Rather than passing every value as a function argument, BindAI exposes the execution context to tools when needed.

---

# Why Use Tool Context?

Tool Context makes tools aware of their environment.

This allows them to:

- Read workflow variables
- Share information with other tools
- Access execution metadata
- Cooperate with workflow nodes
- Participate in complex automation

Without Tool Context, every required value would have to be passed manually.

---

# Execution Context

Internally, BindAI creates an execution context for every run.

```text
Workflow

↓

Execution Context

↓

Agent

↓

Tool
```

The same context is shared throughout the execution.

---

# Reading Variables

Tools can read values created earlier in the workflow.

Example

```python
customer_name = context.variables.get(
    "customer_name",
)
```

If a previous node stored this variable, the tool can immediately use it.

---

# Writing Variables

Tools may also create new variables.

```python
context.variables.set(
    "customer_id",
    42,
)
```

Those variables immediately become available to later workflow steps.

---

# Sharing Data Between Tools

A common workflow looks like this.

```text
Search Customer

↓

customer_id

↓

Load Orders

↓

order_summary

↓

Generate Report
```

Each tool contributes information to the shared execution context.

No manual parameter passing is required.

---

# Using Context in Workflows

Every workflow node shares the same execution context.

```text
Start

↓

Tool A

↓

Tool B

↓

Agent

↓

End
```

Variables created by Tool A are immediately available to Tool B and the agent.

---

# Agent Integration

Agents also participate in the same execution context.

Typical values include:

- Current prompt
- Previous tool outputs
- Structured results
- Workflow variables
- Metadata

This allows the language model to reason over information produced by previous tools.

---

# Example

Suppose an earlier workflow step stores a customer ID.

```python
context.variables.set(
    "customer_id",
    1001,
)
```

A later tool retrieves it.

```python
customer_id = context.variables.get(
    "customer_id",
)
```

No additional parameters are required.

---

# Metadata

Execution context may also store metadata.

Typical examples include:

- Execution ID
- Workflow ID
- Timestamp
- Correlation ID
- User ID
- Custom application metadata

Applications can use metadata for logging and tracing.

---

# Temporary State

Tool Context exists only during one execution.

```text
Execution Starts

↓

Context Created

↓

Workflow Executes

↓

Execution Ends

↓

Context Destroyed
```

Nothing is automatically persisted after execution completes.

---

# Context vs Memory

Tool Context and Memory solve different problems.

| Tool Context | Memory |
|--------------|--------|
| Temporary | Persistent |
| Exists only during one execution | Persists across conversations |
| Stores workflow variables | Stores conversation history |
| Shared between workflow nodes | Shared between user sessions |

Use Tool Context for execution state.

Use Memory for long-term conversational knowledge.

---

# Context vs Function Parameters

Without Tool Context:

```python
generate_report(
    customer_id,
    order_summary,
    tax_rate,
    user_name,
    region,
)
```

With Tool Context:

```python
generate_report()
```

The tool retrieves only the information it needs from the execution context.

This keeps tool signatures small and reusable.

---

# Avoid Global State

Never rely on global variables.

Instead of:

```python
CURRENT_CUSTOMER = ...
```

Prefer:

```python
context.variables.set(
    "customer",
    customer,
)
```

This keeps executions isolated, thread-safe, and predictable.

---

# Best Practices

- Use Tool Context only for execution-specific data.
- Keep variable names descriptive.
- Store only information needed by later steps.
- Avoid storing large objects.
- Never use Tool Context as permanent storage.
- Use Memory when information should survive multiple conversations.
- Prefer Tool Context over global variables.

---

# Summary

Tool Context provides a shared execution environment for agents, workflows, and tools.

It enables tools to exchange information, cooperate with workflow nodes, and access runtime state while keeping tool interfaces clean and reusable.
