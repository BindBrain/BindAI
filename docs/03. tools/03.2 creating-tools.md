# Creating Tools

Tools are Python callables that agents can use during execution.

They allow BindAI applications to perform operations such as:

* Calling APIs
* Querying databases
* Reading files
* Performing calculations
* Executing business logic
* Accessing external services

Creating a tool is intentionally simple: define a Python function and decorate it with `@tool`.

---

# Your First Tool

The simplest tool is a decorated Python function.

```python
from bindai import tool


@tool
def greet(name: str) -> str:
    return f"Hello, {name}!"
```

The `@tool` decorator marks the function as a BindAI tool.

---

# Registering a Tool

Tools can be registered with an agent builder.

```python
from bindai import AgentBuilder


agent = (
    AgentBuilder()
    .tools(greet)
    .build()
)
```

A single tool can also be registered with `tool()`:

```python
agent.tool(greet)
```

Or with `add_tool()`:

```python
agent.add_tool(greet)
```

---

# Automatic Tool Calling

Once a tool is registered, the model can request it during agent execution when appropriate.

For example, with:

```python
@tool
def greet(name: str) -> str:
    return f"Hello, {name}!"
```

a user might ask:

```text
Say hello to Alice.
```

The model can request the tool with the appropriate argument:

```text
greet(name="Alice")
```

BindAI then executes the registered function and makes its result available to the agent execution.

---

# Parameters

Tool parameters come directly from the Python function signature.

```python
@tool
def add(
    a: int,
    b: int,
) -> int:
    return a + b
```

The function communicates that:

* `a` is an integer
* `b` is an integer
* both parameters are required
* the function returns an integer

Use clear parameter names and type annotations.

---

# Optional Parameters

Python default values can be used for optional parameters.

```python
@tool
def search(
    query: str,
    limit: int = 5,
):
    ...
```

The function can be called with only the required parameter:

```text
search(query="BindAI")
```

or with an explicit limit:

```text
search(query="BindAI", limit=10)
```

---

# Type Hints

Type hints are strongly recommended for tools.

Good:

```python
@tool
def weather(
    city: str,
) -> str:
    ...
```

Less descriptive:

```python
@tool
def weather(city):
    ...
```

Type annotations make the tool interface explicit and provide useful information for tool schema generation and argument handling.

Prefer annotations for:

* Strings
* Integers
* Floats
* Booleans
* Collections
* Structured application types

---

# Docstrings

Give tools concise descriptions.

```python
@tool
def exchange_rate(
    from_currency: str,
    to_currency: str,
) -> str:
    """
    Return the exchange rate between two currencies.
    """
    ...
```

A clear description helps communicate what the tool does and when it should be used.

Avoid vague descriptions such as:

```text
Do something.
```

Prefer descriptions that identify the operation and its purpose.

---

# Returning Values

Tools can return values produced by the underlying Python function.

## Strings

```python
@tool
def ping():
    return "Pong"
```

## Numbers

```python
@tool
def square(value: int) -> int:
    return value * value
```

## Lists

```python
@tool
def colors():
    return [
        "red",
        "green",
        "blue",
    ]
```

## Dictionaries

```python
@tool
def profile():
    return {
        "name": "Alice",
        "age": 28,
    }
```

The returned value becomes the tool output used by the agent execution.

---

# Calling APIs

Tools are useful for integrating external services.

For example:

```python
import requests

from bindai import tool


@tool
def get_weather(city: str):
    response = requests.get(
        f"https://example.com/weather/{city}"
    )

    response.raise_for_status()

    return response.json()
```

The agent can then use the tool when a request requires weather information.

For production applications, also consider:

* Request timeouts
* Authentication
* Rate limits
* API failures
* Response validation

---

# Reading Files

A tool can expose controlled file operations.

```python
from pathlib import Path

from bindai import tool


@tool
def read_file(path: str) -> str:
    return Path(path).read_text()
```

Be careful when exposing file-system operations to agents.

Production applications should validate paths and restrict access to files the agent is allowed to read.

---

# Working with Databases

Database operations can also be exposed through tools.

```python
from bindai import tool


@tool
def get_customer(customer_id: int):
    ...
```

Tools can provide controlled access to operations such as:

* Querying records
* Inserting data
* Updating records
* Looking up customers
* Executing business operations

Keep database access behind well-defined functions rather than exposing unrestricted database access to the model.

---

# Multiple Tools

An agent can register multiple tools.

```python
agent = (
    AgentBuilder()
    .tools(
        search,
        get_weather,
        calculate,
    )
    .build()
)
```

The model can select the appropriate registered capability during execution.

For example:

```text
User
  │
  ├── Search request ──► search()
  │
  ├── Weather request ─► get_weather()
  │
  └── Calculation ─────► calculate()
```

---

# Tool Execution

A typical tool-enabled execution looks like this:

```text
User
  │
  ▼
Agent
  │
  ▼
Language Model
  │
  ▼
Tool Request
  │
  ▼
Python Function
  │
  ▼
Tool Result
  │
  ▼
Language Model
  │
  ▼
Final Response
```

The model can use the returned tool output when continuing the execution.

---

# Tool Iterations

Agents can execute multiple rounds of tool calls.

The maximum number of tool iterations can be configured through `AgentBuilder`.

```python
agent = (
    AgentBuilder()
    .max_tool_iterations(5)
    .tools(search, calculate)
    .build()
)
```

This provides a limit on how many tool-execution rounds an agent can perform during a request.

---

# Error Handling

Tools should handle expected failures explicitly.

For example:

```python
from pathlib import Path

from bindai import tool


@tool
def read_file(path: str) -> str:
    try:
        return Path(path).read_text()

    except FileNotFoundError:
        return "File not found."
```

For external APIs and databases, handle expected failures in a similar way.

Useful error handling should provide enough information for the application or agent to understand what happened without exposing unnecessary internal details.

---

# Exceptions

Not every exception should be hidden.

Unexpected programming errors should generally remain visible during development so they can be diagnosed and fixed.

For expected operational failures, prefer controlled handling where appropriate.

For example:

```python
@tool
def divide(a: float, b: float):
    if b == 0:
        return "Division by zero is not allowed."

    return a / b
```

The exact error-handling strategy should depend on whether the failure is expected and recoverable.

---

# Tool Lifecycle

A typical tool-enabled execution follows this lifecycle:

```text
Register Tool
      │
      ▼
Expose Tool
      │
      ▼
Model Chooses Tool
      │
      ▼
Execute Function
      │
      ▼
Return Tool Output
      │
      ▼
Continue Agent Execution
      │
      ▼
Final Response
```

The agent coordinates the interaction between the model and registered tools.

---

# Tool Organization

As projects grow, keep tools separated by responsibility.

For example:

```text
tools/
├── weather.py
├── search.py
├── calculator.py
├── database.py
└── notifications.py
```

Each module can contain related tools.

This makes tools easier to discover, test, and reuse.

---

# Tool Reuse

The same tool can be attached to multiple agents.

```python
weather = get_weather

support_agent.tool(weather)
sales_agent.tool(weather)
research_agent.tool(weather)
```

This avoids duplicating implementations.

When the tool's behavior changes, all agents using that tool receive the updated implementation.

---

# Tool Safety

Tools can perform real operations, so they should be treated as application boundaries.

For sensitive operations:

* Validate inputs
* Restrict accessible resources
* Avoid unrestricted file-system access
* Protect credentials
* Validate external API parameters
* Require explicit authorization where appropriate
* Keep destructive operations narrowly scoped

A language model should not automatically receive unrestricted access to your application.

---

# Execution Context

Some advanced BindAI integrations may need execution context in addition to normal function arguments.

Before documenting a context-injection API, verify the exact supported signature for the version of BindAI being documented.

For standard tools, prefer explicit function parameters:

```python
@tool
def get_customer(customer_id: int):
    ...
```

This keeps the tool interface simple and predictable.

# Complete Example

```python
from bindai import AgentBuilder, tool


@tool
def multiply(
    a: int,
    b: int,
) -> int:
    """
    Multiply two integers.
    """
    return a * b


agent = (
    AgentBuilder()
    .model("openai:gpt-5")
    .instructions("You are a helpful assistant.")
    .tools(multiply)
    .build()
)

result = agent.run("What is 14 × 9?")

if result.success:
    print(result.output)
else:
    print(result.error)
```

The agent has access to the `multiply` tool during execution and can use it when appropriate.

---

# Best Practices

* Keep each tool focused on one responsibility.
* Use descriptive function and parameter names.
* Always add Python type hints.
* Write concise docstrings.
* Return predictable values.
* Handle expected failures gracefully.
* Validate inputs to external systems.
* Restrict sensitive operations.
* Avoid unnecessary side effects.
* Keep long-running operations out of latency-sensitive paths when possible.
* Reuse tools across multiple agents.
* Prefer several focused tools over one large tool.

---

# Summary

Creating a BindAI tool requires very little code:

```python
from bindai import tool


@tool
def greet(name: str) -> str:
    return f"Hello, {name}!"
```

Register it with an agent:

```python
agent.tool(greet)
```

or configure it with the builder:

```python
agent = AgentBuilder().tools(greet).build()
```

Once registered, the tool becomes a capability available during agent execution.

Tools provide the bridge between language-model reasoning and deterministic application code, external services, and real-world operations.
