# Creating Tools

Tools are ordinary Python functions that agents can call during execution.

They allow language models to perform actions they cannot do on their own, such as:

- Calling APIs
- Querying databases
- Reading files
- Executing business logic
- Performing calculations
- Accessing external services

In BindAI, creating a tool is intentionally simple—write a Python function and decorate it with `@tool`.

---

# Your First Tool

```python
from bindai import tool


@tool
def greet(name: str) -> str:
    return f"Hello, {name}!"
```

That's all you need.

The function is automatically converted into a BindAI tool.

---

# Registering a Tool

Register tools when building an agent.

```python
from bindai import AgentBuilder


agent = AgentBuilder().tool(greet).build()
```

Or later:

```python
agent.tool(
    greet,
)
```

---

# Automatic Tool Calling

Suppose the user asks:

```text
Say hello to Alice.
```

The model may internally produce something like:

```text
greet(name="Alice")
```

BindAI then:

1. Validates the arguments
2. Executes the Python function
3. Returns the result to the model
4. Lets the model continue generating its response

The user never sees the internal tool call.

---

# Parameters

Tool parameters are discovered automatically.

```python
@tool
def add(
    a: int,
    b: int,
) -> int:
    return a + b
```

The model knows:

- parameter names
- parameter types
- required fields
- optional values

without any additional configuration.

---

# Optional Parameters

Default values automatically become optional.

```python
@tool
def search(
    query: str,
    limit: int = 5,
): ...
```

The model may call:

```text
search(query="BindAI")
```

or

```text
search(query="BindAI", limit=10)
```

---

# Type Hints

Always use Python type hints.

Good

```python
@tool
def weather(
    city: str,
) -> str: ...
```

Avoid

```python
@tool
def weather(city): ...
```

Type hints improve:

- Validation
- Schema generation
- Tool selection
- Model accuracy

---

# Docstrings

Docstrings become part of the tool description.

```python
@tool
def exchange_rate(
    from_currency: str,
    to_currency: str,
):
    """
    Return the latest exchange rate between two currencies.
    """
```

A good description helps the language model determine when the tool should be used.

---

# Returning Values

Tools may return almost any Python object.

Strings

```python
@tool
def ping():
    return "Pong"
```

Numbers

```python
@tool
def square(
    value: int,
):
    return value * value
```

Lists

```python
@tool
def colors():
    return [
        "red",
        "green",
        "blue",
    ]
```

Dictionaries

```python
@tool
def profile():
    return {
        "name": "Alice",
        "age": 28,
    }
```

BindAI automatically converts the return value into a tool result before passing it back to the model.

---

# Calling APIs

One of the most common uses for tools is API integration.

```python
import requests

from bindai import tool


@tool
def get_weather(city: str):

    response = requests.get(f"https://example.com/weather/{city}")

    return response.json()
```

The agent can now answer questions using live information.

# Error Handling

Handle expected failures inside the tool.

```python
from pathlib import Path

from bindai import tool


@tool
def read_file(path: str):

    try:
        return Path(path).read_text()

    except FileNotFoundError:
        return "File not found."
```

Returning meaningful information is usually better than allowing an unexpected exception to interrupt the conversation.

---

# Tool Lifecycle

```text
Register Tool

↓

Generate Tool Schema

↓

Model Chooses Tool

↓

Validate Parameters

↓

Execute Function

↓

Return Result

↓

Continue Reasoning
```

This lifecycle is identical across all supported providers.

---

# Best Practices

- Keep each tool focused on one responsibility.
- Write descriptive docstrings.
- Always use Python type hints.
- Return predictable outputs.
- Handle expected failures gracefully.
- Prefer deterministic results whenever possible.
- Avoid long-running blocking operations.
- Reuse tools across multiple agents.
- Build several small tools instead of one large tool.

---

# Complete Example

```python
from bindai import AgentBuilder, tool


@tool
def multiply(
    a: int,
    b: int,
) -> int:
    """
    Multiply two integers.
    """
    return a * b


agent = (
    AgentBuilder()
    .model("openai:gpt-5")
    .instructions("You are a helpful assistant.")
    .tool(multiply)
    .build()
)

result = agent.run("What is 14 × 9?")

print(result.output)
```

The language model automatically decides to call the `multiply` tool, receives the result, and generates the final answer.
