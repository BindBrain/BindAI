# Templates Overview

The **Templates** section provides practical examples of the BindAI workflow system.

These templates demonstrate common workflow execution patterns, including sequential execution, conditional branching, loops, parallel execution, human-in-the-loop tasks, retry handling, timeout protection, and scheduled execution.

Each template focuses on one workflow capability while showing how that capability behaves within the BindAI workflow runtime.

---

# Purpose

The workflow templates are designed to:

* demonstrate workflow execution patterns
* explain how workflow nodes interact
* show how execution state is managed
* demonstrate failure and recovery behavior
* illustrate long-running and paused workflows
* provide practical examples of workflow orchestration

The templates are intended to complement the workflow implementation and documentation.

# Basic Workflow

The workflow templates build on the same general execution model.

A basic workflow follows a sequence of nodes:

```text
Start

↓

Node

↓

Next Node

↓

End
```

The executor manages the execution queue and determines which node should execute next.

The basic workflow template provides the foundation for understanding the more advanced templates.

# Conditional Execution

The condition template demonstrates automatic branching based on workflow state.

Conceptually:

```text
Node

↓

Condition

↙       ↘

True    False

↓         ↓

Path A   Path B
```

Conditions allow a workflow to choose different execution paths without requiring manual intervention.

---

# Loops

The loop template demonstrates intentional repetition within a workflow.

Conceptually:

```text
Condition

↓

Continue?

↙       ↘

Yes      No

↓         ↓

Process   Continue

↓

Loop
```

Loops are useful when workflow logic must repeat until a predicate becomes false.

A loop is different from retry handling: a loop represents intentional repetition, while retry responds to node execution failures.

---

# Parallel Execution

The parallel template demonstrates execution of multiple workflow branches.

Conceptually:

```text
Start

↓

Parallel

↙        ↘

Branch A  Branch B

↓        ↓

Join

↓

Continue
```

Parallel execution allows independent branches to progress before a join point continues the workflow.

# Human Tasks

The human template demonstrates workflows that pause while waiting for human input.

Conceptually:

```text
Agent

↓

Human Task

↓

Waiting

↓

User Action

↓

Resume

↓

Continue
```

The workflow context stores the human task and enters a waiting state.

The workflow can later be resumed after the human task has been completed.

This pattern supports human-in-the-loop workflows such as approvals, reviews, and validation.

---

# Retry

The retry template demonstrates executor-level recovery from failed node execution.

When a node raises an exception and a `RetryPolicy` is configured, the executor can execute the node again.

Conceptually:

```text
Execute Node

↓

Exception

↓

Retry Policy

↓

Try Again
```

The retry policy controls the maximum number of attempts.

The current implementation supports:

```python
RetryPolicy(
    max_attempts=3,
    delay_seconds=5,
    exponential_backoff=True,
)
```

The executor currently uses `max_attempts` to control retries.

The configured delay and exponential backoff fields are not currently applied by the executor, so retries occur immediately.

---

# Timeout

The timeout template demonstrates execution-time protection.

A `TimeoutPolicy` defines the maximum total workflow duration.

Conceptually:

```text
Workflow Start

↓

Execute Node

↓

Check Timeout

↓

Within Limit?

↙          ↘

Yes         No

↓            ↓

Continue    Fail
```

The executor compares the current time with the workflow's `started_at` timestamp before node execution.

If the configured limit has been exceeded, the workflow fails with:

```text
Workflow timeout.
```

Timeout detection occurs between node executions and does not forcibly interrupt a node that is already running.

---

# Scheduling

The schedule template demonstrates time-based workflow scheduling.

A `WorkflowSchedule` contains:

* `workflow_id`
* `next_run`
* `interval_seconds`
* `enabled`

The `WorkflowScheduler` provides operations for:

```text
add()

↓

due()

↓

reschedule()
```

The scheduler determines which registered schedules are due but does not execute workflows itself.

The surrounding application is responsible for starting the corresponding workflow execution.

Recurring schedules are advanced by adding `interval_seconds` to `next_run`.

# Learning Path

A practical order for learning the workflow system is:

```text
Workflow Basic

↓

Condition

↓

Loop

↓

Parallel

↓

Human

↓

Retry

↓

Timeout

↓

Schedule
```

The basic template introduces normal execution first.

Conditions, loops, and parallel execution then introduce increasingly complex control flow.

Human tasks introduce paused and resumable execution.

Retry and timeout introduce execution reliability and safety.

Scheduling introduces application-level time-based workflow execution.

# Templates and Implementation

The templates describe behavior provided by the BindAI workflow runtime.

Important implementation responsibilities include:

* workflow node execution
* execution queue management
* workflow state
* waiting and resumption
* retry handling
* timeout checking
* scheduling state
* execution history
* workflow events
* persistence

The templates should therefore be read together with the corresponding workflow implementation and node documentation.

---

# Best Practices

When using the workflow templates:

* start with the basic workflow
* understand the execution queue before studying advanced control flow
* distinguish intentional loops from retries
* treat human tasks as long-running waiting states
* use retry policies for recoverable node failures
* use timeout policies to limit total workflow duration
* keep scheduling separate from workflow execution
* design recurring workflows so repeated execution is safe
* inspect execution events and history when troubleshooting failures
