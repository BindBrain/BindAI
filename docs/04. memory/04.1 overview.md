# Memory Overview

Memory enables BindAI agents to retain information across conversations and executions.

Without memory, every interaction starts with a blank context. With memory enabled, an agent can remember previous discussions, user preferences, and important facts to provide more natural and personalized responses.

Memory integrates directly with agents, workflows, and projects while remaining provider-independent.

---

# What is Memory?

Memory stores information that an agent can retrieve later.

Typical examples include:

- previous conversations
- user preferences
- important facts
- long-term context
- execution history

Instead of asking users to repeat information every session, the agent can recall it automatically.

---

# Why Memory Matters

Consider the following conversation.

```text
User:
My name is Alice.

Assistant:
Nice to meet you, Alice.
```

Later:

```text
User:
What's my name?
```

Without memory:

```text
Assistant:
I don't know.
```

With memory enabled:

```text
Assistant:
Your name is Alice.
```

Memory makes conversations feel continuous instead of isolated.

---

# How Memory Works

During every execution, BindAI performs the following steps:

```text
Load Memory

↓

Build Prompt

↓

Generate Response

↓

Store Updated Memory
```

The agent automatically retrieves relevant memories before contacting the language model and stores new information afterward.

---

# Memory Architecture

```text
User

↓

Agent

↓

Memory Provider

↓

Language Model

↓

Response

↓

Memory Updated
```

Memory providers are responsible for storing and retrieving information, while the execution engine manages when memory is accessed.

---

# Conversation Memory

The simplest form of memory stores previous messages.

Example:

```text
User:
I live in London.

Assistant:
Great!
```

Later:

```text
User:
Where do I live?
```

The execution engine loads previous messages so the model can answer correctly.

---

# Long-Term Memory

Memory is not limited to a single conversation.

Depending on the configured provider, information may persist across:

- multiple conversations
- multiple application sessions
- workflow executions
- application restarts

This allows assistants to build long-term relationships with users.

---

# Memory Providers

BindAI separates memory behavior from storage.

Common providers include:

- In-memory
- Redis
- PostgreSQL
- Custom providers

Because every provider implements the same interface, switching storage backends requires little or no application code changes.

---

# Attaching Memory

Memory is attached directly to an agent.

```python
agent.use_memory(memory)
```

After registration, the execution engine automatically loads and stores conversation history.

---

# Memory in Workflows

Memory is shared naturally throughout workflow execution.

```text
Start

↓

Agent A

↓

Memory Updated

↓

Agent B

↓

Memory Available

↓

End
```

Later workflow steps can access information created earlier without manually passing it between nodes.

---

# Memory vs Knowledge

Memory and Knowledge solve different problems.

| Memory | Knowledge |
|---------|-----------|
| Stores conversation history | Stores external information |
| Changes during execution | Usually static |
| User-specific | Shared across users |
| Personal context | Reference documents |

Use **Memory** for conversations.

Use **Knowledge** for documentation and retrieval.

---

# Memory vs Workflow Variables

Workflow variables exist only while a workflow executes.

Memory persists beyond execution.

| Workflow Variables | Memory |
|--------------------|--------|
| Temporary | Persistent |
| Execution scope | Conversation scope |
| Cleared after execution | Retained between sessions |

Variables coordinate workflow logic.

Memory provides conversational continuity.

---

# Common Use Cases

Memory is commonly used for:

- remembering user names
- storing user preferences
- tracking previous conversations
- continuing multi-session tasks
- maintaining personalized assistants

---

# Best Practices

- Store only useful information.
- Avoid saving unnecessary messages.
- Use Memory for user-specific context.
- Use Knowledge for documents and reference material.
- Select a storage provider appropriate for your application.
- Consider retention policies for production deployments.

---

# Summary

Memory gives BindAI agents continuity across conversations.

By automatically loading previous context before generation and storing new information afterward, agents can provide more personalized, context-aware experiences while keeping application logic simple.
