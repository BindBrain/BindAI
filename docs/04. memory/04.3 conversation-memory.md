# Conversation Memory

Conversation Memory enables BindAI agents to remember previous interactions with a user.

Instead of treating every request as independent, the agent can retrieve earlier messages and include them in the next model request, allowing conversations to continue naturally across multiple exchanges.

---

# What is Conversation Memory?

Conversation Memory stores the sequence of messages exchanged between a user and an agent.

Example:

```text
User:
My favorite programming language is Python.

Assistant:
Python is a great choice.
```

Later:

```text
User:
Which language did I say I liked?
```

With conversation memory enabled:

```text
Assistant:
You said your favorite programming language is Python.
```

Without memory, the assistant would have no knowledge of previous interactions.

---

# How It Works

Every interaction follows the same lifecycle.

```text
Load Conversation

↓

Append User Message

↓

Generate Response

↓

Store Updated Conversation
```

This process happens automatically whenever a memory provider is attached to an agent.

---

# Attaching Memory

Enable conversation memory by attaching a memory instance.

```python
agent.use_memory(memory)
```

No additional code is required to save or retrieve messages.

---

# Conversation Lifecycle

Each conversation grows as new messages are exchanged.

```text
User

↓

Assistant

↓

User

↓

Assistant

↓

User

↓

Assistant
```

Every interaction becomes part of the conversation history.

---

# Building the Model Request

Before contacting the language model, BindAI assembles the request using:

- system instructions
- conversation history
- current user message

```text
System Prompt

+

Conversation History

+

Current User Message

↓

Language Model
```

This gives the model the context needed to produce coherent responses.

---

# Example

Conversation begins:

```text
User:
My company is Acme.
```

Later:

```text
User:
Write an email to my company.
```

Because previous messages are available, the assistant understands that *"my company"* refers to **Acme**.

---

# Multiple Conversations

Conversation memory is typically isolated by session.

```text
Conversation A

↓

History A


Conversation B

↓

History B
```

Each conversation maintains its own independent history.

---

# Conversation Growth

Over time, conversation history becomes larger.

```text
Message 1

↓

Message 2

↓

Message 3

↓

...

↓

Message N
```

Applications can choose different strategies for managing long conversations.

---

# Managing Long Conversations

Large language models have finite context windows.

When conversations become very large, common approaches include:

- keeping only recent messages
- summarizing older messages
- archiving completed conversations
- retrieving only relevant history
- combining memory with retrieval (RAG)

These strategies help maintain performance while preserving important context.

---

# Conversation Memory vs Knowledge

Although both provide context, they serve different purposes.

| Conversation Memory | Knowledge |
|---------------------|-----------|
| Previous conversations | External documents |
| User-specific | Shared information |
| Dynamic | Usually static |
| Personal context | Reference material |

Conversation Memory remembers what users have said.

Knowledge retrieves information from external sources.

---

# Conversation Memory in Workflows

Conversation memory is available throughout workflow execution.

```text
Start

↓

Agent

↓

Conversation Updated

↓

Another Agent

↓

Conversation Loaded

↓

End
```

Multiple agents can participate in the same conversation without manually passing messages between them.

---

# Clearing Conversations

Applications may decide when conversations should end.

```text
Conversation Ends

↓

Memory Cleared

↓

New Conversation Starts
```

Whether conversations are retained or deleted depends on the configured memory provider and your application's requirements.

---

# Best Practices

- Keep conversations focused on a single topic.
- Avoid storing unnecessary or temporary messages.
- Use summaries for long-running conversations.
- Combine conversation memory with knowledge retrieval for factual information.
- Isolate conversations by user or session.
- Define retention policies for production applications.

---

# Summary

Conversation Memory allows BindAI agents to maintain continuity across interactions.

By automatically loading previous messages before generation and storing new messages afterward, agents can deliver more coherent, context-aware, and personalized conversations while keeping application code simple.
