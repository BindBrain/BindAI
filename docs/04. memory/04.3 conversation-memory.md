# Conversation Memory

BindAI provides a memory system that allows applications to store and retrieve information across agent executions.

Memory is exposed through the `Memory` abstraction and can be attached to an agent with `use_memory()`.

The current memory system is record-based rather than being limited to a specific conversation-history format.

---

# What is Conversation Memory?

Conversation-related information can be stored as memory records and retrieved during later executions.

A memory record contains a key, value, namespace, and additional metadata.

```python
from bindai import MemoryRecord

record = MemoryRecord(
    key="favorite_language",
    value="Python",
)
```

The record can then be stored in a `Memory` instance.

```python
from bindai import Memory

memory = Memory()

memory.set(record)
```

---

# Attaching Memory to an Agent

An agent can use a `Memory` instance through `use_memory()`.

```python
from bindai import Agent, Memory

memory = Memory()

agent = Agent(
    model="openai:gpt-5",
)

agent.use_memory(memory)
```

The agent now has access to the configured memory system.

The memory implementation remains separate from the agent itself.

```text
Agent

↓

Memory

↓

Memory Provider
```

---

# Storing Conversation Information

Applications can store conversation-related information explicitly.

For example:

```python
from bindai import Memory, MemoryRecord

memory = Memory()

memory.set(
    MemoryRecord(
        key="favorite_language",
        value="Python",
        namespace="user-123",
    )
)
```

The namespace can be used to separate information belonging to different users or conversations.

---

# Reading Memory

Stored information can be retrieved using `get()`.

```python
result = memory.get(
    "favorite_language",
    namespace="user-123",
)
```

The result is returned through BindAI's memory result interface.

Applications can then use the retrieved value when constructing prompts or performing other application logic.

---

# Searching Memory

Memory also provides a search operation.

```python
results = memory.search(
    "favorite programming language",
    namespace="user-123",
)
```

The search operation accepts:

* a query
* a namespace
* a result limit
* optional metadata filtering

For example:

```python
results = memory.search(
    "programming preferences",
    namespace="user-123",
    limit=5,
)
```

The exact retrieval behavior depends on the configured memory provider.

---

# Namespaces

Namespaces provide isolation between groups of memory records.

For example:

```python
MemoryRecord(
    key="favorite_language",
    value="Python",
    namespace="user-123",
)
```

and:

```python
MemoryRecord(
    key="favorite_language",
    value="JavaScript",
    namespace="user-456",
)
```

These records use the same key but belong to different namespaces.

Retrieving one does not require accessing the other namespace.

```python
memory.get(
    "favorite_language",
    namespace="user-123",
)
```

Namespaces are therefore useful for separating:

* users
* conversations
* tenants
* applications
* other logical memory scopes

---

# Conversation Memory Pattern

An application can use memory to preserve important conversation information.

A simple pattern is:

```text
User Message

↓

Extract Important Information

↓

Store MemoryRecord

↓

Later User Message

↓

Search/Get Memory

↓

Build Model Request

↓

Generate Response
```

For example, an application might store:

```python
MemoryRecord(
    key="company",
    value="Acme",
    namespace="user-123",
)
```

Later, application code can retrieve the value:

```python
result = memory.get(
    "company",
    namespace="user-123",
)
```

The retrieved information can then be included in the next model request.

---

# Conversation History vs Memory Records

Memory records should not automatically be treated as a complete transcript.

A memory record stores structured information such as:

```text
key
value
namespace
metadata
```

For example:

```python
MemoryRecord(
    key="company",
    value="Acme",
)
```

This is different from storing an entire sequence of:

```text
User message
Assistant message
User message
Assistant message
```

Applications that need full conversation transcripts should explicitly implement that storage pattern using the available memory primitives or another application-level storage system.

---

# Memory Records and Metadata

Conversation-related records can contain metadata that helps applications organize and retrieve information.

```python
record = MemoryRecord(
    key="favorite_language",
    value="Python",
    namespace="user-123",
    metadata={
        "source": "conversation",
    },
    tags=["preference"],
)
```

Records also support fields such as:

* importance
* access count
* expiration
* tags
* source
* relationships
* timestamps
* embeddings

This allows applications to build richer memory systems without changing the core storage API.

---

# Deleting Memory

A specific memory record can be deleted.

```python
memory.delete(
    "favorite_language",
    namespace="user-123",
)
```

Applications can use this when information is no longer relevant or when a user requests that stored information be removed.

---

# Clearing Memory

Memory can also be cleared for a namespace.

```python
memory.clear(
    namespace="user-123",
)
```

This provides a simple way to remove all memory associated with a particular namespace.

---

# Checking for Memory

Applications can check whether a record exists.

```python
exists = memory.exists(
    "favorite_language",
    namespace="user-123",
)
```

This can be useful before attempting to retrieve or overwrite a value.

---

# Conversation Memory and Providers

Conversation-related memory uses the same provider architecture as the rest of BindAI's memory system.

```text
Application

↓

Agent

↓

Memory

↓

MemoryProvider

↓

Storage
```

The current package includes:

* `InMemoryProvider`
* `SQLiteMemoryProvider`
* `VectorMemoryProvider`

The application can therefore choose the storage implementation according to its requirements.

---

# Conversation Memory in Workflows

Memory can also be used by application workflows.

A workflow can store information under a namespace and later retrieve it.

```text
Workflow Step

↓

MemoryRecord

↓

Memory

↓

Later Workflow Step

↓

Memory.get() / Memory.search()
```

This provides persistent or temporary information exchange depending on the selected provider.

The workflow itself does not need to know the implementation details of the underlying provider.

---

# Managing Long Conversations

Long conversations can produce large amounts of information.

BindAI's memory API provides primitives that applications can use to manage this information, including:

* namespaces
* search
* deletion
* clearing
* metadata
* tags
* expiration
* importance
* memory lifecycle management

Applications can build their own policies for deciding what should be retained and what should be removed.

---

# Memory Lifecycle

Memory records contain lifecycle-related information.

For example, `MemoryManager` provides operations for:

* reinforcing records
* weakening records
* increasing or decreasing importance
* setting expiration
* clearing expiration
* touching records
* promoting records
* forgetting records

Example:

```python
from bindai import MemoryManager

manager = MemoryManager()

manager.set_expiration(
    record,
    days=30,
)
```

This allows applications to implement retention and lifecycle policies for stored information.

---

# Best Practices

* Use namespaces to isolate users or conversations.
* Store useful structured information rather than unnecessary data.
* Use metadata and tags when records need additional organization.
* Use `search()` when retrieval should be query-based.
* Use `get()` when a specific key is known.
* Use expiration for temporary information.
* Delete or clear information when it is no longer required.
* Use persistent providers when memory must survive application restarts.
* Do not assume that a `MemoryRecord` is automatically a complete conversation transcript.

---

# Summary

BindAI provides a flexible memory system that can be used to implement conversation-aware applications.

The core primitives are:

```text
Memory
│
├── MemoryRecord
├── get()
├── set()
├── search()
├── delete()
├── exists()
└── clear()
```

Agents can attach memory using:

```python
agent.use_memory(memory)
```

Conversation memory is therefore built around BindAI's general memory abstraction rather than requiring the application to depend on a provider-specific storage API.

The application decides what conversation information to store, how it is organized, and when it should be retrieved or removed.
